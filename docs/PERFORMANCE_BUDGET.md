## 1. 目的

本项目首先优化长期运行时的 CPU、唤醒频率和内存，不以最小安装包体积牺牲稳定性、
透明窗口正确性或角色表现。存储空间允许适度增加，但所有缓存都必须有来源、预算和清理规则。

预算不是为了追求一次漂亮的截图，而是为了约束：

- 开机后长时间静置的真实占用；
- 可见、隐藏、静态和动画状态之间是否真正降载；
- 切换角色和打开控制面板时是否出现不可控峰值；
- PetPack 是否能通过预解码和磁盘缓存换取更低运行时负担；
- 发布物和用户数据是否随着版本迭代无界增长。

性能 gate 不得通过降低正确性、跳过验证或篡改测量口径来规避。

## 2. 优先级

发生权衡时，固定使用以下顺序：

1. 稳定性、透明窗口与数据正确性；
2. 空闲 CPU 和系统唤醒；
3. 常驻内存；
4. 动画期间 CPU 与帧稳定性；
5. 启动、面板和角色切换延迟；
6. 安装与缓存磁盘占用。

磁盘可以换 CPU，但必须满足缓存可重建、可限额、可清理且不混入事实收据。

## 3. 测量术语

### 3.1 CPU

主指标为单核等效 CPU：

    single_core_cpu_percent =
        process_cpu_time_delta / wall_time_delta * 100

它表示一个逻辑处理器满载为 100%，不使用任务管理器按全机核心数摊薄后的数字。

进程外采样间隔为 250 ms。每种稳定状态先预热 60 秒，再连续测量至少 10 分钟。
预热后的全部样本都进入平均值；只有 harness 预先声明并以 marker 划定的场景转换区间
可以从某个稳定态分段，不能事后把短峰值排除。每个场景报告：

- 10 分钟全样本平均；
- 5 秒滚动均值的 P95；
- 超过硬上限的最长连续时长；
- 原始 250 ms 样本峰值。

CPU 表中的目标和硬上限同时约束全样本平均与 5 秒滚动均值 P95；任一超限均按对应等级判定。

### 3.2 内存

主指标为 Windows Private Bytes，Private Working Set 为辅助指标。每份报告同时记录：

- Private Bytes；
- Private Working Set；
- 线程数；
- Handles；
- GDI Objects 和 USER Objects；
- 切换峰值及切换完成 60 秒后的回落值。

不得只用 Python 对象大小或 RSS 的单点截图代替进程级测量。

### 3.3 延迟

应用内部使用单调时钟输出结构化 marker：

- process_start；
- tray_ready；
- first_pet_paint；
- panel_requested / panel_first_paint；
- character_switch_requested / first_character_paint；
- hidden / resumed。

启动 T0 由进程外 harness 在 CreateProcess 成功时记录，T1 为应用内部 first_pet_paint；
启动耗时等于 T1 - T0，从而覆盖 PyInstaller bootloader、Python、Qt plugin 与 DLL 加载。
process_start 只用于内部阶段分析，不能作为正式启动 T0。

暖启动、OS 文件缓存尽量冷却后的冷启动、应用 --startup 延迟，以及“用户登录到桌宠出现”的
自启端到端时间分别报告。默认登录延迟不计入程序冷启动，但不能从自启端到端报告中消失。

每项至少运行 20 次，报告 P50、P95 和最差值。首帧必须是候选角色已验证后的可显示帧，
不能用空 QWidget、占位矩形或旧角色帧提前结束计时。

### 3.4 磁盘

分别报告：

- 核心 onedir 目录；
- 默认内置角色；
- 已安装 PetPack revisions；
- 缩略图缓存；
- 渲染或解码缓存；
- 回滚保留；
- 日志、收据、数据库和 journal。

不得把可清理缓存与不可替代的原始归档、权利声明或安装收据合并为一个数字。

## 4. 参考环境

发布候选至少在以下环境实测：

### 4.1 低配参考机

- Windows 11 x64；
- 4 核 8 线程；
- 8 GiB 内存；
- 集成显卡；
- SSD；
- 1920×1080，100% DPI。

### 4.2 主流参考机

- Windows 11 x64；
- 8 核 16 线程；
- 16 GiB 内存；
- 集成或独立显卡；
- SSD；
- 双屏，混合 100% / 150% / 200% DPI。

性能 gate 使用正式 onedir Release 和独立测试数据目录执行，不使用 IDE、调试器或
QT_QPA_PLATFORM=offscreen 的结果代替。虚拟机可用于回归趋势，不能单独冻结最终阈值。

每份正式报告还必须记录精确 CPU/GPU 型号、Windows build、GPU driver、显示刷新率、
电源模式、AC/电池、Defender 与索引状态、HDR、远程桌面状态以及是否发生热降频。
冻结前指定至少一台带稳定硬件 ID 的命名参考设备。

## 5. 标准负载

### 5.1 参考 PetPack

固定维护并哈希以下参考包：

- MinimalStatic：静态 256 或 512 逻辑画布，只含 core.idle；
- StandardLayered：普通分层角色，常用动作与短音频；
- StandardSequence：12 帧轻动画；
- ComplexSequence：24 帧、512×512、透明序列动画；
- WideAndTall：极宽和极高角色，用于布局和缓存压力；
- LibraryPressure：20 个系列、200 个角色、200 张缩略图。

普通参考包压缩体积建议不超过 30 MiB；单个当前动作的解码资源建议不超过 40 MiB。
这两个数值是参考负载定义，不代替 PETPACK_SPEC_1_0.md 的安全硬上限。

### 5.2 稳定状态

所有目标至少覆盖：

- 窗口隐藏；
- 可见静态；
- 轻量 idle 动画；
- 普通循环动作；
- 复杂序列动作；
- 控制面板打开；
- 标准角色切换；
- 200 角色库浏览。

## 6. 内存预算

以下均为主进程 Private Bytes：

| 状态 | 目标值 | 硬上限 |
|---|---:|---:|
| 内置静态角色、面板关闭 | 100 MiB | 130 MiB |
| 普通 idle 动画 | 130 MiB | 160 MiB |
| 普通动作与短音频 | 150 MiB | 180 MiB |
| 控制面板和角色库打开 | 190 MiB | 230 MiB |
| 原子角色切换瞬时峰值 | 230 MiB | 280 MiB |

规则：

- 目标值用于持续优化；硬上限是发布 gate。
- 切换成功后 60 秒内必须释放旧角色 Runtime 和无引用资源。
- 面板连续打开关闭 100 次后，不得持续增加 QObject、缩略图或对话框实例。
- 24 小时增长目标为不超过 max(20 MiB, 20%)；超过 max(50 MiB, 30%) 为硬失败；
  两者之间标记目标未达，只有有效 P1 豁免才可发布。
- 线程、Handles、GDI 和 USER 对象不得呈单调无界增长。

### 6.1 当前角色缓存

每个 active Runtime 的缓存预算：

| 类别 | 目标 |
|---|---:|
| idle 所需解码资源 | 24 MiB |
| 当前动作额外资源 | 24 MiB |
| active Runtime 总缓存 | 48 MiB |
| active Runtime 硬上限 | 64 MiB |

缩略图、非当前角色和磁盘预解码缓存不计入该表，但必须分别限额。QPixmap/QImage 缓存必须按
估算解码字节计费并采用 LRU；不得使用无界字典。

控制面板缩略图 RAM cache 目标 32 MiB、硬上限 64 MiB，并已经包含在“控制面板和角色库打开”
的主进程 190/230 MiB 总预算中，不得在报告中扣除或重复加算。
控制面板同时只保留一个预览 Runtime；其内存计入面板总预算，与候选切换并发时还受 280 MiB
切换峰值硬上限约束。面板关闭或预览结束后 30 秒内必须释放预览媒体和重型缩略图缓存。

## 7. CPU 与唤醒预算

| 状态 | 单核等效 CPU 目标 | 硬上限 |
|---|---:|---:|
| 隐藏、锁屏或会话断开 | 0.2% | 0.5% |
| 可见静态 | 0.5% | 1.0% |
| 轻量 idle 动画 | 1.0% | 2.0% |
| 普通循环动作 | 3.0% | 5.0% |
| 复杂序列动作 | 5.0% | 8.0% |

实现约束：

- VisualClock 与 ServiceClock 必须分离。
- 隐藏、锁屏或真正静态时，VisualClock 触发次数必须为零。
- ServiceClock 仅维持倒计时、日程和恢复所需低频工作，不执行绘制流水线。
- 倒计时稳定时每秒最多重算一次，不得随动画帧重算。
- 动作内容帧率是解析后的唯一有效帧率；8 FPS 内容不得按 16 FPS 重复 repaint。
- 恢复后不得追补隐藏期间的每一帧。
- 音频解码、缩略图生成和包扫描不得长期占用 GUI 线程。

硬上限冻结前需在至少三台真实设备校准一次。校准只能修正明显不公平的测量环境，
不能因实现超限而临时移动 gate。

## 8. 响应时间预算

| 操作 | 目标 | 硬上限 |
|---|---:|---:|
| 热启动到首个有效桌宠帧 P95 | 2.0 s | 5.0 s |
| 标准角色切换到新角色首帧 P95 | 2.0 s | 5.0 s |
| 切换期间空白窗口 | 0 ms | 100 ms |
| 首次打开控制面板 P95 | 1.5 s | 3.0 s |
| 再次打开控制面板 P95 | 0.5 s | 1.5 s |
| 点击到可见反馈 P95 | 200 ms | 400 ms |
| 从隐藏恢复到有效帧 P95 | 300 ms | 1.0 s |

角色切换采用双 Runtime 两阶段提交；旧角色继续显示，直到候选角色通过验证并产生首帧。
因此正常路径的空白目标为零。

任一单次运行超过对应硬上限的 2 倍，直接失败，不得被 P95 稀释。标准包与重型但合规包在
第一次 calibration 后分别冻结门槛；表中较宽的切换上限暂用于重型包，标准包应以 1 秒目标、
2 秒硬上限作为校准起点。

### 8.1 帧稳定性

标准与复杂参考包在 100%、150% 和 200% DPI 分别报告：

- frame render time P95；
- frame interval jitter P95；
- deadline hit ratio；
- dropped/coalesced frame ratio；
- input-to-paint latency；
- 同内容帧重复 repaint 比例；
- 首次解码尖峰。

正式数值与其它性能值一同 PROVISIONAL 校准并冻结。CPU 达标但存在肉眼卡顿、持续 deadline miss
或输入反馈超限，不能判为通过。

## 9. 磁盘预算

### 9.1 核心发布物

- onedir 核心发布物理想范围：100–120 MiB；
- 超过 150 MiB 必须在发布报告中列出模块贡献和保留理由；
- PROVISIONAL 硬上限为 200 MiB；超过或相对当前约 131 MiB 基线增长超过 20%，
  必须 NO-GO 等待用户明确批准，实施者不能自行豁免；
- 默认内置安全角色单独列账。

当前 1.1.1 精确 artifact 为 121.33 MiB、259 个文件，身份见
[项目更新](PROJECT_UPDATES.md)。约 131 MiB 是迁移前历史基线；两者都不替代三台
参考设备上的 Production 预算冻结。

### 9.2 用户数据

| 类别 | 目标值 | 上限或策略 |
|---|---:|---|
| 缩略图磁盘缓存 | 64 MiB | 128 MiB，LRU |
| 渲染/预解码磁盘缓存 | 128 MiB | 256 MiB，LRU |
| 自动回滚保留 | 256 MiB | PROVISIONAL |
| 回滚保留时间 | 7 天 | PROVISIONAL |
| 活动日志 | 10 MiB | 20 MiB |

原始 PetPack 归档、当前与上一健康 revision、权利声明和安装收据不因普通缓存清理被删除。
超出回滚预算时，先删除未激活且不再受保护的旧 revision；删除必须进入生命周期 journal。

## 10. 长期运行与退化

发布候选执行至少一次 24 小时 soak。固定脚本每小时包含：20 分钟轻动画、10 分钟静态、
10 分钟隐藏、10 分钟普通动作、一次面板打开/关闭和一次两角色往返切换；每 6 小时运行一次
200 角色库浏览，另设独立、人工辅助的睡眠/恢复场景。音频使用固定短 fixture，不使用用户音乐。
开始和结束都回到同一内置参考角色、面板关闭、静态且缓存完成回收的状态；预热 10 分钟后的值
作为内存增长基线。任何失败都保留从开始到失败的全部样本。

- 周期性切换轻动画、静态、隐藏和恢复；
- 打开关闭面板；
- 切换两个参考角色；
- 模拟日程、工作、休息和倒计时更新；
- 记录每分钟资源指标和关键事件。

失败条件：

- 进程崩溃或失去托盘恢复入口；
- 角色窗口变成普通 Windows 窗口、抢焦点或进入 Alt+Tab；
- 内存超过硬上限或持续增长；
- 线程、句柄、GDI 或 USER 对象持续增长；
- 隐藏状态仍执行绘制；
- ServiceClock 停止导致倒计时或日程丢失；
- 旧角色资源无法在切换后回收。

## 11. 报告与证据

每个发布候选保存：

- commit、构建哈希、PySide6/Qt/Python 版本；
- Windows 构建、CPU、内存、GPU、屏幕和 DPI；
- 参考包 revision digest；
- 原始 CSV 或 JSONL 采样；
- 汇总报告；
- marker 时间线；
- dist size manifest；
- 测量脚本版本；
- 所有超限、豁免、原因和到期版本。

正式结果和探索结果分层标记。探索数据不得覆盖发布 gate 的原始测量，发布摘要不得删除失败样本。

## 12. 预算冻结程序

1. 先实现标准 fixture、结构化 marker 和进程外采样；
2. 在低配与主流参考机运行；
3. 对明显测量噪声进行一次口径校准；
4. 记录冻结日期和样本；
5. 将数值从 PROVISIONAL 改为 FROZEN；
6. 后续只能用新版本修订，不覆盖旧预算和旧报告。

如果实现超限，优先定位时钟、重复 repaint、资源解码、缓存和 Qt 模块引入原因；
不得为了通过检查而降低采样时间、排除失败设备或修改已有结果。

六项未完成的正式环境门禁及角色库近期资源风险见[未来工作](FUTURE_WORK.md)。
