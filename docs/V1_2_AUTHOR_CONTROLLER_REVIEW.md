## CR-T01 / P1：序列帧读取层级错误，非法时长也会 lint clean

位置：`scripts/petpack_cli.py::_action_frames()`、`_budget_report()`。
实际协议把帧放在 `lifecycle.loop.renderer.frames`，实现却遍历
`section.get("frames")`，导致符合协议的序列被当作零帧。

独立合成一个 2 帧、时长为 500/700 ms 的包，validate 与 GUI 同门禁 preflight
均通过；lint 返回 0 并打印 `frames=0 total_ms=0 decoded~0 KiB`、预算 0.0 MiB
及 `lint result clean`。把其中一帧改成 1 ms 后，validator 拒绝，lint 仍 clean。

要求：与 Runtime/协议统一取帧位置，正确报告帧数、总时长和解码资源量；明确
处理空序列、非正/过短时长、超帧数和缺失资产。补有效多帧与无效时长测试，
用独立预期值断言，不能只检查输出包含 contact/budget 两个字符串。

## CR-T02 / P1：preview 没有经过实际角色绘制与 geometry

新增复杂交互窗口。sequence 使用真实帧时间取样，覆盖不等帧长、循环接缝与动作
回退；保留无库、无 Context、无配置修改和静音约束。补竖图/大留白/偏置锚点的
几何输出断言，不以“调用了 Runtime 的解码器”替代“经过 Runtime 绘制”。

### CR-T03 继续开放 / P2：接触图标签不可读且越过文本区域

在本机用独立 CLI 进程运行 preview，打开实际 `contact-demo.png`，动作语义、
帧序号、时长和回退说明均为缺字方框；回退说明还从 132 px 标签区跨入图像区。
这并非只发生在主控复用 QApplication 的探针中，独立进程同样复现。

当前 `_write_contact_sheet` 只构造默认 QFont 并检查是否画出暗像素，没有保证
该字体在 offscreen 环境下能显示标注。请选择/加载具备所需字形的字体，检查
字形可用性；环境确实缺字体时明确报告原因，不生成声称成功的不可读接触图。
不要把某台机器的个人字体路径硬编码进公开实现。

文本使用有边界的布局，长说明换行、缩写或省略，不能压到样本图上。补独立 CLI
进程下的字形与文字边界检查，并打开实际产物验收。无需更改整体美术风格或做
额外复杂 UI。

### CR-T04 / P2：16 列限制恰好遗漏 16 帧序列的最后一帧

`preview_schedule()` 先为每帧生成起点，再追加接缝，然后以
`MAX_PREVIEW_COLUMNS=16` 截成前 15 个采样加接缝。

独立构造 16 帧序列，实际 frame_index 列表为 `[0,1,...,14,None]`，最后一帧
15 没有取样；None 是循环回到首帧的 seam。这样无法查看真实“末帧→首帧”过渡，
而本项目 Blender 首批恰好允许 8–16 帧。序列较长时只留前部也没有明确提示被省略。

要求：16 帧 MVP 至少完整导出 16 帧和接缝；接触图可换行或分页，不必无限加宽。
长序列如需有界抽样，须保留首帧、末帧与接缝，明确标注采样/省略范围；不要静默
把前 15 帧当成整个动作。实现者可自行选择版式与上限。

验收：16 帧中最后一帧使用明显不同的合成形状/颜色，证明导出与接触图包含它，
接缝则回到首帧。再测至少一个超过上限的序列，检查输出有界且省略信息明确。
