## 角色库历史技术债快照（2026-09-12）

以下列表保留为 1.2.0 实施前的审计输入，其中多项已由 V12-02/03/07 解决；
不要将它直接当作当前开放工单。仍开放的内容方向以“当前问题台账”为准。

1. PetPack 规范要求 `package.publisher_ref`，当前 validator 和半写实示例都没有
   落实。应先决定补实现还是修订规范，再增加 conformance fixture。
2. `petpack_cli.py init` 只生成骨架，规范目标中的独立 `preview` 与 `install-local`
   尚未实现；GUI 仍是唯一正式安装入口。
3. 构建器使用固定 ZIP 信息时没有设置成员压缩类型，半写实 0.1.0 与 0.1.1 的三个
   成员均为 `ZIP_STORED`。官方包有防覆盖保护，canonical 示例还缺同等级保护。
4. geometry 目前没有完整字段校验，Runtime 也没有用它计算正文区域、锚点和点击区。
   在修复前，作者只能靠 PNG 物理画布控制桌面比例。
5. 半写实包声明需要 `renderer.sequence.v1`，实际三个动作都是 `static`。应先审计
   它是否有意代表当前 static/sequence renderer family；在 capability 语义冻结前，
   不修改 manifest 或已钉扎摘要。
6. 规范要求激活提交有追加式生命周期事件，当前实现需要补一次针对
   `ACTIVATE_COMMITTED` 的 conformance 审计。
7. 角色页主要按系列与角色展示。多个 Revision 并存时，还需要显示 package ID、
   版本、digest、来源和当前/上一健康状态，避免出现难以区分的重复条目。

## 接下来五段工作

### R1 半写实退休猫 0.2

先锁定角色身份页、正侧面比例、配色和毕业帽细节。素材源可以高分辨率保存，桌宠
输出建议统一到 512×512 透明画布，脚底锚和可见边界保持稳定。首批交付至少包含
独立 idle、work、rest，随后补 eat、exercise、meeting、music。

每个动作先做一张稳定姿态，再决定是否扩成短序列。这样可以尽早验证画风、窗口
占比和角色一致性，不必一次制作大量返工成本很高的帧。

R1 的最低验收包括真实 Alpha、透明四角、无烘焙文字、无场景或投影、动作间身份
一致、预检通过；切换失败不能错误提交目标角色，并须按可证明权威回滚、恢复或进入
Bootstrap 安全模式。static 角色不引入额外素材解码循环或帧序列推进，并以相同
场景的 CPU 样本确认没有明显回退。

#### R1-Blend-01 更拟真退休小猫 Blender 动画 MVP

Blender 只作为离线创作工具，不引入实时 3D Runtime。先确定奶油/桃色毛发、暖色
大眼睛和深蓝毕业帽等身份锚点，再用一份可继续编辑的主 `.blend` 保存模型、材质、
毛发、骨骼、动作、相机、灯光、透明 Film 与渲染设置。源工程、高分辨率纹理和草稿
放在 PetPack 源目录之外；PetPack 构建目录只接收协议允许的发布素材，避免把 `.blend`
误装入角色包。

首批 Runtime 交付为 512×512 RGBA PNG：一个 2–4 秒无缝 idle 循环，建议 8–16 个
有意义的离散帧，外加独立的 work/rest 静态姿态。相机、角色比例、脚底锚、四边留白
和透明角必须跨动作稳定，不带文字、logo、背景、地面或烘焙阴影。单帧时长不得低于
33 ms；idle 解码预算以 24 MiB 为上限预检，运行时角色缓存仍保持 48 MiB 上限。

1.2.0 已修复正常待机的 `elapsed_ms` 推进，并让 Runtime 正式消费 geometry/
脚底锚，素材序列现在可以进入实际验收。确认 idle/work/rest 的桌面效果后，再制作
eat、exercise、meeting、music。发布为新
PetPack `0.2.0`，不得覆盖 0.1.1；同时更新来源、许可、AI/第三方素材与权利记录，
并通过两次确定性构建、validate、preflight 和 inspect。

### R2 作者工具和模板

状态：**1.2.0 已完成基础作者闭环**。以下目标已经由 V12-03 实现并验收；新增格式
能力仍须按独立版本进入规范和 Runtime，不能因为工具能解析就直接承诺支持。

把 `petpack_cli.py init` 升级为可校验的完整静态模板，增加 manifest lint、画布与
锚点检查、动作接触图（contact sheet）、序列时长报告和离线预览。构建仍保持
确定性。ZIP 压缩方式变化会改变 archive SHA，但相同内容仍可能保持同一 content
digest；工具与发布 artifact 必须新增证据。0.1.0 canonical 是内部冻结旧事实，
0.1.1 是当前公开与运行时 pin，二者均不得原地覆盖。只有 manifest 或包内容改变时
才提升 PetPack 版本。

### R3 角色库管理

角色页增加系列筛选、角色详情、版本与来源、资产预算、当前/上一健康 Revision、

### R4 多系列内容

### R5 Todo 轻量增强

状态：**1.2.0 已完成 schema v2、四象限、归档与长备注基础；1.3.0 继续完善交互**。

现有短期/中期/长期表示时间跨度，不与重要/紧急四象限混为同一字段。1.2.0 已在
保留子任务树和单焦点的基础上增加四象限、完成项隐藏、可恢复归档和按需长备注。
1.3.0 将恢复有明确子树数量的物理删除入口，增加显式 self/subtree 完成范围，并让
重要/紧急状态在主树中一眼可见。

schema v2 的迁移、迁移前备份、失败回滚和旧库 fixture 已完成。近期范围仍是个人
本地轻量 Todo，不扩展云同步、多人协作、附件、富文本编辑器或常驻索引服务。

#### R5-MD-01 备注 Markdown 轻量预览

状态：**NEXT，已纳入 V13-04**。1.2.0 的备注数据安全和主控验收已完成，Qt 原生
Markdown 预览不需要新增数据库 schema，因此作为 1.3.0 的轻量必交增强。

初步评估：项目现有 PySide6 6.8.3 已提供 `QTextBrowser.setMarkdown()` 和
`QTextDocument.setMarkdown()`，基本预览可复用现有依赖。建议保留纯文本编辑，
增加“编辑 / 预览”切换，先支持标题、列表、强调、引用和代码块等基本排版。
数据库继续保存原始 Markdown 文本，预览不回写或格式化源文，不需要新增 schema。
预览按需构建与释放，遵守当前本地备注的数据和资源边界，不自动加载外部图片。

后续实施前做小范围验证：中文、换行和 Emoji 正常；编辑/预览切换不改原文、不
丢草稿；保存及备份恢复仍使用同一备注数据。公式、Mermaid、所见即所得编辑和
复杂插件暂不纳入此项。若基本预览也需要重做编辑器或引入重型组件，则保留为
后续候选，不为本项扩大当前返工。

## Production 尚需的六项门禁

1. 100%、150%、200% 混合 DPI，负坐标副屏、跨屏和拔屏恢复；须先修复多屏脚本，
   不得把未覆盖的拓扑记为 PASS。
2. 真实注销与登录后的自启、不抢焦点和启动延迟。
3. 锁屏、会话断开、睡眠与唤醒。
4. 无 Python、无 Anaconda 且存在竞争 Qt PATH 的干净 Windows 11 VM。
5. 绑定同一 artifact 的完整 24 小时稳定性观测。
6. 三台参考设备的 10 分钟性能样本和预算冻结。

这些项目可以与角色创作并行准备，但在取得原始证据前必须继续显示
`PRODUCTION-NO-GO:PENDING_ENVIRONMENT`。

## 暂不进入近期范围

在线角色商店、自动下载和云同步保持 `EXPLORATORY`，只有经过独立的产品、内容治理
与网络安全决策后才可能进入路线。Live2D、Spine、3D 等外部运行时同样保持
`EXPLORATORY`；只有 raster 正式案例证明表达不足，并同时给出 CPU、内存、包体与
安全预算时，才重新讨论。受限的纯数据 `rig/layered` 仍属于 `PLANNED`。PetPack 内
第三方可执行代码是冻结的禁止项，不属于探索范围。
