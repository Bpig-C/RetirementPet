## 1. 项目愿景

RetirementPet 是一个常驻 Windows 桌面的透明桌宠。它以“陪伴用户直到退休”为核心叙事，展示固定目标时间的倒计时，并通过待机、工作、休息、用餐、健身、会议、音乐和键鼠互动等动作反馈用户的日常节奏。

产品应保持三个特征：

1. **安静陪伴**：默认不抢焦点、不频繁弹窗、不干扰输入。
2. **有生命感**：通过呼吸、眨眼、摆尾、视线和情境动作形成连续反馈。
3. **长期可维护**：动作、素材、配置和平台能力彼此解耦，新增动作不需要修改窗口核心。

## 2. 当前基线

现有程序已经具备：

- 无边框、透明、置顶的 QWidget 窗口；
- 基于 `QPainter` 的卡片、文字和程序化猫咪绘制；
- 固定退休时间 `2060-07-07 21:32:00` 的实时倒计时；
- 青年、中年、晚年、退休四阶段外观；
- 鼠标拖动；
- 右键菜单；
- 基于 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的开机自启开关。

必须保留的行为：

- 倒计时始终以系统当前时间与固定目标时间相减，不采用递减计数；
- 休眠、关机、进程重启后倒计时仍准确；
- 开机自启只写当前用户注册表，不请求管理员权限；
- 退出动作必须可发现；
- 程序不记录具体按键内容。

## 3. 范围

### 3.1 v1 范围

- 默认待机、随机动作和鼠标互动；
- 工作、休息、干饭、健身、会议、音乐动作；
- 动作优先级、打断、冷却和回退；
- 分层 PNG 与少量序列帧混合渲染；
- 本地配置、窗口位置与用户偏好持久化；
- Windows 空闲时间检测；
- 托盘菜单、单实例、开机自启；
- PyInstaller `onedir` 发布；
- 日程的手动设置和本地规则。

### 3.2 暂不纳入 v1

- 记录键盘内容、截屏或监控具体应用内容；
- 云端账户、遥测、广告和自动上传；
- Live2D、3D 引擎或强依赖 GPU 的渲染；
- 自动控制麦克风、摄像头或会议软件；
- 未经用户确认的在线更新；
- 深度绑定某一个日历或音乐平台。

## 4. 总体架构

建议采用“QWidget 宿主 + 动作控制器 + 分层渲染器”的渐进式架构，不在 v1 直接迁移到 QML。

```text
main
  ├─ SingleInstanceGuard
  ├─ SettingsStore
  ├─ RetirementPetWindow
  │    ├─ PetRenderer
  │    ├─ CountdownPanel
  │    └─ Context/Tray Menu
  ├─ ActionController
  │    ├─ ActionRegistry
  │    ├─ RandomActionScheduler
  │    └─ ScheduleManager
  ├─ ActivityMonitor
  ├─ AudioManager
  └─ StartupManager
```

核心约束：

- 窗口只处理输入、位置、显示和绘制，不决定业务动作；
- 渲染器只根据当前动画快照绘制，不自行切换动作；
- 动作控制器是唯一可改变主动作的组件；
- 日程、键鼠状态和菜单仅提交“动作请求”；
- 音频由独立管理器控制，动作退出时必须释放或停止对应音效；
- 所有跨模块通知使用 Qt signal/slot，避免循环引用。

## 6. 核心数据模型

建议在 `models.py` 定义：

```python
class ActionId(str, Enum):
    IDLE = "idle"
    BLINK = "blink"
    STRETCH = "stretch"
    INTERACT = "interact"
    WORK = "work"
    REST = "rest"
    EAT = "eat"
    EXERCISE = "exercise"
    MEETING = "meeting"
    MUSIC = "music"

@dataclass(frozen=True)
class ActionSpec:
    action_id: ActionId
    priority: int
    min_duration_ms: int
    max_duration_ms: int | None
    cooldown_ms: int
    interruptible: bool
    loop: bool
    animation_fps: int
    weight: float = 0.0

@dataclass(frozen=True)
class ActionRequest:
    action_id: ActionId
    source: str
    requested_at: datetime
    force: bool = False
    payload: Mapping[str, Any] = field(default_factory=dict)
```

运行时状态与定义分开：

```python
@dataclass
class ActionRuntime:
    spec: ActionSpec
    started_at_ms: int
    frame_index: int = 0
    payload: dict[str, Any] = field(default_factory=dict)
```

不要让 UI 直接修改 `ActionRuntime`。

## 7. 动作状态机

### 7.1 优先级建议

| 请求来源 | 建议优先级 | 示例 |
|---|---:|---|
| 用户强制选择 | 100 | 菜单中立即健身 |
| 会议 | 90 | 进入预定会议时间 |
| 用餐/健身日程 | 75 | 午饭、每日拉伸 |
| 用户互动 | 65 | 点击、抚摸、拖动结束 |
| 工作/休息 | 50 | 活跃工作、长时间空闲 |
| 随机动作 | 20 | 伸懒腰、舔爪 |
| 默认待机 | 0 | 呼吸、摆尾 |

### 7.2 切换规则

动作请求仅在以下条件之一满足时生效：

1. 当前无动作；
2. 请求优先级高于当前动作且当前动作可打断；
3. 当前动作达到最短持续时间并自然结束；
4. 用户发出 `force=True` 的明确指令；
5. 当前动作失效，例如会议时间结束。

任何动作结束后均回到 `IDLE`，再由控制器处理队列中的有效请求。过期请求不得补播。

### 7.3 冷却与防抖

- 同一随机动作在冷却期内不能再次入选；
- 眨眼是叠加动画，不应取代主动作；
- 鼠标连续移动只更新目标点，不重复创建互动请求；
- 工作/休息状态至少稳定 10 秒后才切换；
- 日程提醒每天记录一次处理状态，避免每次启动重复提醒。

### 7.4 主动作与叠加层

将视觉状态拆为：

- **主动作层**：idle、work、rest、eat、exercise、meeting、music；
- **表情层**：眨眼、微笑、困倦、专注；
- **附件层**：电脑、耳机、麦克风、饭碗、哑铃；
- **特效层**：音符、Zzz、汗滴、提示气泡；
- **信息层**：退休倒计时卡片。

眨眼和视线跟随不应打断工作或会议动作。

## 8. 动作定义

### 8.1 默认待机

- 身体按正弦曲线轻微上下缩放，周期约 2.5–4 秒；
- 尾巴缓慢摆动，方向和幅度略随机；
- 3–8 秒随机眨眼，偶尔双眨；
- 鼠标在附近时眼睛朝光标偏移，最大偏移受限；
- 长时间无其他事件时保持低 CPU 占用。

### 8.2 随机动作

首版包含伸懒腰、舔爪、左右张望、打哈欠。每个动作配置权重、持续时间和冷却时间。随机调度器每 8–15 秒评估一次，而不是每帧抽签；默认平均间隔建议 45–120 秒。

### 8.3 键鼠互动

- 左键点击：短表情或气泡；
- 双击：展开/收起倒计时面板；
- 拖动：移动宠物，释放后弹性回稳；
- 鼠标悬停：视线跟随；
- 滚轮：默认调节宠物音量，可在配置中关闭；
- 系统空闲时间用于判断工作和休息，不采集具体按键、文本或鼠标轨迹历史。

Windows 空闲检测采用 `GetLastInputInfo`。检测失败时返回未知状态，不得错误判断为长期空闲。

### 8.4 工作

- 持续键鼠活跃超过阈值进入工作；
- 显示电脑/书本附件和敲击动画；
- 连续工作达到用户设定时长后发出柔和休息提示；
- 不根据窗口标题或输入内容推断用户工作内容。

### 8.5 休息

- 用户空闲超过阈值或主动开始休息时进入；
- 闭眼、趴卧、Zzz 等低频动画；
- 恢复输入后延迟数秒再返回工作/待机，避免频繁切换；
- 可支持番茄钟，但默认关闭。

### 8.6 干饭

- 默认仅由用户配置的早餐、午餐和晚餐窗口触发；
- 提供“开始吃饭”“稍后提醒”“今天跳过”；
- 同一餐次每天最多主动提醒一次；
- 动画结束不代表用户已经吃饭，只有用户确认才记录完成。

### 8.7 健身

- 由固定日程、久坐提醒或用户手动触发；
- 首版可提供 30–120 秒拉伸倒计时；
- 不提供医疗判断；
- “稍后提醒”应有限次数，避免骚扰。

### 8.8 会议

- v1 支持手动会议模式和本地时间段；
- 会议模式下关闭随机音效，视觉动作保持克制；
- 可显示耳麦、记事本或“勿扰”标记；
- 日历导入作为后续适配器，不让核心动作控制器依赖某个日历服务。

### 8.9 音乐

- 使用 `QMediaPlayer` 和 `QAudioOutput`；
- 支持本地文件播放、暂停、上一首、下一首和音量；
- 用户音乐文件不打包进 EXE；
- 保存文件路径前进行存在性校验；
- 播放失败只显示非阻塞提示，不影响宠物主循环。

## 9. 绘制与动画

### 9.1 v1 渲染方案

采用混合方式：

- 卡片、倒计时和简单特效继续用 `QPainter`；
- 猫咪主体采用透明分层 PNG；
- 呼吸、摆尾、抬头使用部件位移、旋转和缩放；
- 伸懒腰、吃饭等形变复杂动作使用 PNG 序列帧；
- 配饰作为独立图层复用。

### 9.2 坐标系统

素材使用统一设计画布，例如 256×256。渲染器先在逻辑坐标中组合，再映射到窗口目标区域。禁止在各动作中散落窗口像素坐标。

建议绘制顺序：

```text
阴影 → 后侧附件 → 身体 → 尾巴 → 头部 → 眼睛/表情
     → 前侧附件 → 粒子/气泡 → 倒计时面板
```

### 9.3 帧率

- 动画主时钟建议 16 FPS；
- 倒计时文本每 250–1000ms 更新一次；
- 窗口不可见或屏幕锁定时降频或暂停动画；
- 不为每个动作建立永久 QTimer；统一由动画时钟驱动。

### 9.4 素材清单

最低可用素材：身体、头、尾巴、睁眼、闭眼、左右爪、电脑、耳机、耳麦、饭碗、哑铃、Zzz、音符。所有 PNG 应为透明背景，使用相同画布和锚点。

`assets/manifest.json` 记录动作、帧路径、FPS、循环方式、锚点和附件。缺失素材时渲染器应回退到程序化猫咪或默认待机，不得崩溃。

## 10. 窗口与交互

- 宠物主体透明，倒计时面板默认可折叠；
- 首次启动放在主屏幕右下角；
- 保存窗口所在屏幕和相对位置；
- 屏幕拔插、分辨率变化后将窗口约束回可见区域；
- 支持“始终置顶”和“鼠标穿透”开关；
- 鼠标穿透启用后必须能从托盘菜单恢复；
- 右键菜单保留退出、自启，并增加动作、设置、显示/隐藏；
- 系统托盘图标作为隐藏窗口后的恢复入口。

## 11. 配置与持久化

```text

├─ settings.json
├─ state.json
```

`settings.json` 示例：

```json
{
  "schema_version": 1,
  "target_datetime": "2060-07-07T21:32:00",
  "always_on_top": true,
  "startup_enabled": false,
  "countdown_panel_expanded": true,
  "animation_fps": 16,
  "random_actions_enabled": true,
  "random_action_min_interval_s": 45,
  "random_action_max_interval_s": 120,
  "sound_enabled": true,

  "work_idle_threshold_s": 120,
  "rest_reminder_minutes": 50,
  "meal_times": ["08:00", "12:00", "18:30"],
  "exercise_times": ["16:00"]

```

规则：

- 缺失字段使用默认值；
- 未知字段保留，便于向前兼容；
- 配置写入采用临时文件加原子替换；
- 损坏配置备份为 `.broken-时间戳` 后恢复默认值；
- 密码、令牌和隐私数据不进入该配置。

## 12. 单实例与生命周期

必须避免开机自启和用户手动启动产生多个宠物。建议使用 `QLocalServer/QLocalSocket`：

- 首个进程创建固定 server name；
- 后续进程连接成功后发送 `show`，然后退出；
- 首个进程收到 `show` 后显示窗口并置前；
- 崩溃遗留 server 时安全清理后重试；
- server name 应包含应用 ID 和当前用户范围标识。

退出流程：停止调度器、保存位置和状态、停止播放器、释放托盘图标，然后结束 Qt 事件循环。

## 13. 开机自启

沿用当前用户注册表 Run 项：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
RetirementPet = "<install-root>\RetirementPet.exe" --startup
```

要求：

- 只在用户明确勾选时写入；
- 取消时只删除 `RetirementPet` 自己的值；
- 启动时检查注册表路径是否仍指向当前 EXE；
- 移动安装目录后提示用户修复，而非静默写入；
- `--startup` 模式可以延迟 5–15 秒启动，以避开登录高峰；
- 调试脚本不得意外覆盖正式 EXE 的自启项。

## 14. 打包与发布

### 14.1 环境

项目环境固定在：

```text
<project-root>\.venv
```

依赖至少固定：

```text
PySide6==6.8.3
PyInstaller>=6,<7
```

不要复用 Downloads 中的临时环境作为正式构建环境，也不要在同一环境混装 Conda Qt 和 pip PySide6。

### 14.2 构建策略

正式发布优先 `onedir`：

```powershell
python -m PyInstaller `
  --noconfirm `
  --clean `
  --windowed `
  --onedir `
  --name RetirementPet `
  --add-data "assets;assets" `
  --icon "assets\icons\retirement_pet.ico" `
  src\retirement_pet\main.py
```

建议最终产物：

```text
<project-root>\dist\RetirementPet\RetirementPet.exe
```

构建脚本必须从脚本自身推导项目根目录，不依赖调用者的当前目录。

### 14.3 版本信息

EXE 应包含产品名、文件描述、公司/作者、语义版本和版权信息。版本号遵循 `MAJOR.MINOR.PATCH`。每次正式构建记录依赖锁定文件和构建时间。

## 15. 日志与异常处理

- 默认日志级别 INFO，滚动文件单个不超过 1–2 MB，保留 3 份；
- 不记录按键内容、完整音乐目录或敏感日历正文；
- 顶层 Qt slot 捕获可预期异常并记录；
- 资源缺失、音频失败和配置损坏应降级，不应导致进程退出；
- 无法创建窗口或 Qt 核心依赖加载失败才视为致命错误；
- `--debug` 模式可开启控制台和更详细日志，正式版默认无控制台。

## 16. 性能目标

建议验收目标：

- 待机 CPU 平均低于 1%，复杂动画尽量低于 3%；
- 常驻内存目标低于 200 MB；
- `onedir` 冷启动目标低于 3 秒；
- 普通桌面缩放 100%–200% 下显示清晰；
- 长时间运行不持续增长内存、timer 或 signal 连接数量；
- 音乐关闭时不初始化不必要的音频资源。

这些是工程目标，不应为了数字而牺牲稳定性；测试需注明硬件与测量方式。

## 17. 测试计划

### 17.1 单元测试

- 目标时间前后与退休时刻的倒计时；
- 年龄阶段边界；
- 高优先级动作打断低优先级动作；
- 不可打断动作的最短持续时间；
- 冷却、随机权重和过期请求；
- 配置缺失字段、损坏恢复和版本迁移；
- 源码与 frozen 模式资源路径；
- 自启命令生成，不在单元测试中真实修改注册表。

时间相关测试必须注入 clock，不直接依赖 `datetime.now()`。

### 17.2 集成测试

- 单实例第二次启动能唤起首个实例；
- 启用/关闭自启后注册表值正确；
- 屏幕变化后窗口仍可见；
- 音频文件不存在时程序继续运行；
- 素材缺失时回退渲染；
- 工作、休息、会议状态不会被随机动作覆盖。

### 17.3 打包冒烟测试

在未安装 Python 的 Windows 用户环境中验证：

1. EXE 可启动且无控制台；
2. 倒计时准确；
3. 透明、置顶、拖动和菜单正常；
4. 素材与声音正常加载；
5. 开机自启生效；
6. 再次启动不会出现第二只宠物；
7. 退出后进程和托盘图标消失；
8. MiKTeX 等其他 Qt 软件在 PATH 中时仍能运行。

## 20. 决策记录

### ADR-001：v1 保留 QWidget

原因：现有实现基于 QWidget/QPainter，渐进重构风险低。QML 可在后续视觉复杂度确实超过 QWidget 能力时评估，不作为当前目标。

### ADR-002：分层 PNG + 序列帧

原因：分层部件适合呼吸、摆尾、视线和附件复用；复杂形变用少量序列帧补足，在表现力、素材成本和打包复杂度之间平衡较好。

### ADR-003：正式发布使用 onedir

原因：Qt 单文件模式启动时需要解压，登录启动速度和杀毒软件兼容性通常不如 onedir。单文件版只能作为可选分发形式。

### ADR-004：隐私优先的活动检测

原因：产品只需了解“活跃或空闲”，无需获取具体输入。采用系统最后输入时间即可满足需求并显著降低隐私风险。

### ADR-005：本地规则先于平台集成

原因：会议和日程平台适配会引入授权、网络与兼容性成本。核心体验先通过手动模式和本地规则完成，未来以适配器扩展。

## 21. 完成定义

项目达到 v1 完成状态需同时满足：

- 八类核心行为可用且状态切换符合优先级；
- 默认动画连续自然，素材缺失有回退；
- 倒计时、拖动、折叠面板、托盘和退出稳定；
- 配置、窗口位置和提醒状态可持久化；
- 不采集具体键鼠内容，无默认网络请求；
- 单实例和当前用户开机自启可靠；
- 关键逻辑有自动化测试；
- `onedir` 包能在干净 Windows 环境运行；
- 文档、默认配置、依赖和构建脚本与实际实现一致。
