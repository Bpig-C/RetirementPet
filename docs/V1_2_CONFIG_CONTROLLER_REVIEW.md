### CR-U07：容量上限不能静默淘汰失败草稿

位置：`ui/panel/todo_page.py::_keep_draft()`，第 859–863 行。
当前满 16 条时直接 `drafts.pop(next(iter(drafts)))`，丢掉的恰是没有成功落盘
的用户内容，没有提示，也没有第二个恢复来源。

复现：创建 17 个合成任务，让备注写入持续失败，逐个输入不同内容并保存；重新
选择第一项，草稿库只有 16 条，首项内容已经不在草稿库，数据库和编辑器均为空。
原来的跨面板保存修复有效，但这一新淘汰策略仍违反“不丢未保存内容”。

要求：容量满时采用不丢既有草稿的有界策略，例如暂停接纳新草稿并明确反馈，或
使用受控恢复暂存；具体方案自行选择。正常保存成功后回收空间。验证第 16/17
条、关面板重开、故障解除后重试；不能仅用 dict 长度不超过 16 证明正确。

### CR-U08：恢复发布后失败被错误宣称原库未动

位置：`TodoPage::_on_backup_restore()`，第 1054–1058 行。
`except BackupError` 无条件显示“所选备份无法使用，现有数据未改动”。服务层
早已区分 `restore_publish_unknown`（os.replace 已完成，后续持久化屏障失败）
和替换前失败，此处丢掉了这个关键区别。

真实按钮路径复现：备份中 1 项，当前库 2 项；仅在替换后的 live DB fsync 注入
OSError。恢复界面显示“现有数据未改动”，而存储/服务已只有 1 项，备份之后的
任务不在当前库。旧数据仍有 pre-restore 备份，但界面关于当前库的断言是假的。

要求：消费稳定错误阶段/原因，未知发布结果不能宣称未改动；根据重新打开结果
刷新存储事实，并给出 pre-restore 恢复路径。将同一注入场景通过 UI 测试，
同时保留替换前失败、仅重开失败、再次恢复自修复的独立覆盖。

### CR-C01：从磁盘载入坏模板会阻止启动

位置：`app.py::_render_text_template()`，第 1849–1853 行；
`config_system.py::UiConfigService.reload()`。

隔离 settings.json 中仅放入 `ui_text_templates.countdown_text` 的 501 字
字符串，构造真实 PetApplication 即抛出 `TextSafetyError: text too long`。
原因是 effective() 内部校验发生在 try 外；reload 只判断 str，没有排除非法
模板，所以 `_apply_layout_config()` 的初始标题同步中断启动。

要求：不可信的持久化值须在载入/解析边界降级到上次有效值或默认值，并明确
记录配置无效；不能让错误逃出启动或 Qt 回调。覆盖全局/角色模板、超长、禁止
字符、未知布局和非法布局组合；验证应用仍能启动、页面可打开和恢复默认。

### CR-C02：动作控件存在，但实际不可点击

位置：`ui/panel/pages.py::build_actions_page()` 的 controls_form/逐动作
wrapper，约第 708–784 行。

实际 720×480 Qt 面板中，十个 action_trigger 按钮的几何高度全部为 0；相应
模式和循环行也被压缩，截图只剩动作名称。首次默认打开的较高面板截图同样未见
这些控件。findChild 能找到控件且 `.click()` 可以发信号，不能证明用户能用。

要求：提供可滚动内容或能维持控件最小高度的布局，在支持的最小窗口尺寸能看到
并操作全部动作。测试按钮/下拉/勾选框的有效几何和可达性，通过实际坐标点击
至少一个控件；打开截图检查。文案页顶部的长说明也应换行，避免压窄导航与截字。
这属于功能可用性，不能留到最后作为美化处理。

### CR-C03：布局和策略需要成组验证、成组提交

位置：`pages.py::build_display_page.on_apply/on_reset` 第 975–999 行；
`UiConfigService` 目前仅提供逐字段保存。

三个独立结果：

1. 从合法 focus+dnd 选择合法 standard+normal，先保存 layout 时仍拿旧 dnd
   验证，导致 standard+dnd 被拒，合法目标组合无法一次应用。
2. standard+normal 改 pet_only+quiet，第一次保存成功、第二次注入失败：
   磁盘/解析结果已变 pet_only+normal，窗口仍 standard，界面却称“设置未改变”。
   重启后还会意外采用已半提交的 pet_only。
3. focus+quiet 下让保存返回 False，再点恢复默认：有效值和磁盘保持 focus+
   quiet，界面却显示“已恢复默认布局与可见性”。on_reset 忽略了返回结果。

要求：以整组候选验证允许矩阵，一次保存发布两个值；失败恢复完整旧组及窗口
状态；恢复默认也必须可区分失败和未配置。穷举允许组合之间的切换，而不仅是
标准默认→pet_only。覆盖每个落盘失败点及重启结果。

### CR-C04：动作配置失败回滚漏掉原本不存在的键

位置：`app.py::_set_action_mode()` / `_set_action_loop()` 第 1868–1901 行。

从没有 ui_action_modes/ui_action_loops 的设置开始，令 save 返回 False，
通过动作页将 yawn 禁用、work 关闭循环。界面称“保存失败，设置未改变”，但
运行时 `_action_mode('yawn') == 'disabled'`、`_action_loop('work') == False`。
随后另一次正常 settings.save 会把这些失败改动写进磁盘。

要求：按原键的存在与否精确回滚，控件、内存和磁盘保持一致；恢复控件时屏蔽
信号，避免再次触发写入。验证首改失败、覆盖既有值失败、无关设置随后保存和
重启；循环与模式两条路径都覆盖。

### CR-C05：动作页当前表演不更新且观察对象错误

位置：`build_actions_page.refresh_current()` 第 654–666 行及 activate。

复现：打开动作页显示 core.idle；点击 stretch 后控制器当前动作确为 stretch，
标签仍是 core.idle。随后设 WORKING Context，控制器变 work，页面仍是
core.idle。`bridge.last_performance` 只记录 Context 推导结果，手动表演不更新
它；页面只在 activate/按钮成功时刷新，普通事实变化和自然结束也不订阅。

要求：展示实际主表演，并将真实缺素材回退/来源一并展示；活动页订阅变化，
离开/关闭时解除订阅。覆盖手动开始、自然结束、Context 切换、角色切换和重新
打开，不用常驻高频轮询。模式行标签和已有控件也须跟随有效状态，不能长期留
在构造时的“自动”。

### CR-C06：核心动作禁用与循环的范围不完整

位置：`app.py::_request_manual_action()`、`random_actions.py` 的 mode_allowed，
`context_adapter.py::PerformanceBridge.apply()`、`action_controller.py::_activate()`。

实际将 rest 设为 disabled，再令 RESTING Context 生效，主表演仍为 rest。
模式只挡新按钮和 RANDOM_ACTION_IDS 候选，没有进入 Context 推导的主表演
选择；因此报告“禁用即彻底消失”不成立。不要以清除 Context 事实来掩盖这个问题。

另据代码：循环关闭只是把默认 work/rest 的无上限 duration 改成 10000ms；
它没有读取当前角色序列总时长，不能称为“只播放一次素材循环”。现有测试仅断言
duration 非 None，没有验证实际序列的末帧/停止时机或自动发起路径。

要求：明确并实现模式对可控自动表演的约束，保持会议/勿扰等真实事实与安全规则；
对不能被该控件控制的行为明确标识，不能提供表面禁用。循环开关仅在有真实支持
时开放，验证一个非 10 秒的序列能按声明单次/循环播放，或者改为准确的有限时长
控制并如实说明范围，不把有限 duration 当作一次素材循环的证据。
