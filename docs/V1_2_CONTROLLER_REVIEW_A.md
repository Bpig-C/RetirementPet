## 2. 必须返工的发现

### CR-A01 / P1：恢复输入会被本次保留清理删除

位置：`todo/backup.py` 的 `restore_backup()`，先调用
`create_backup(..., "pre-restore")`，之后才打开并复制候选。

独立复现：创建 8 个有效手动备份，选择最旧的一个恢复。新增 pre-restore 备份触发
第 9 份清理，恰好删掉正在恢复的输入；结果为 `restore_publish_failed`，所选备份
目录消失。当前库仍在，但用户的恢复点已被此次恢复操作删掉。

要求：整个恢复操作保护输入，或先生成并校验独立恢复暂存，再在安全阶段清理。
同样保护本次 pre-restore 副本。验收需覆盖满额备份、最旧输入、迁移前输入、失败
重试和同一秒创建多个备份，不能只测试尚未达到保留上限的往返。

### CR-A02 / P1：清理没有验证备份归属，会删除外来目录

位置：`todo/backup.py` 的 `_read_manifest()`、`list_backups()`、`prune_backups()`。
当前 manifest 入口仅验证 format；清理候选只要求 kind 非空，未验证 app/database
归属和完整元数据。

独立复现：在合成数据目录放置一个符合名称前缀、`format=1`、`kind=manual`，但
`app=another-app`、`database=other.db` 的用户目录；已有 8 份合法备份后运行清理，
该目录及其中的 canary 文件被删除。现有“不碰外来目录”测试只覆盖没有 manifest
的目录，未覆盖可解析但不属于本应用的 manifest。

要求：验证应用、数据库归属、kind、路径边界和足以证明管理归属的元数据；归属
不明保留并报告。补外来/损坏 manifest、不同库名及路径重解析边界测试。无需向
用户请求许可来放宽“不得删除其他文件”的既有要求。

### CR-A03 / P1：恢复发布后的异常造成缓存与落盘状态分裂

位置：`todo/backup.py` 的 `os.replace()` 后 fsync，以及
`todo/service.py` 的 `restore_from_backup()` 异常分支。

独立复现：备份含 1 项，当前服务含 2 项；让替换文件后的 fsync 抛 OSError。调用
报告 `restore_publish_failed`，磁盘已经恢复成 1 项，服务却保留 2 项旧缓存；随后
重命名旧缓存中的第 2 项，会把已经被恢复移除的任务重新插回数据库。

要求：区分发布前失败与发布后状态，失败时重新取得可信磁盘状态，重建任务缓存、
焦点投影与 UI 事件；不能证明状态时进入禁写故障态。也可按明确策略保全并恢复
原库，但不能声称“异常时当前库未变”而继续使用旧缓存。增加 replace/fsync/重开
失败边界测试，验证失败之后的下一次编辑不会写入陈旧任务。

### CR-A04 / P2：隐藏与会话暂停没有联合判断

位置：`app.py` 的 `_on_session_suspended()` 与 `_show_window()`。
两种原因都直接调用同一个 pause/resume，解除其中一种会抹掉另一种暂停原因。

独立复现：显示后累计 300 ms，隐藏，再模拟睡眠与唤醒，保持窗口隐藏并前进
1000 ms。窗口仍不可见，timeline 却未暂停，累计变为 1300 ms；不符合承诺的
“隐藏时间不推进”。

要求：由可见性与会话状态共同确定时间轴是否运行，或跟踪独立暂停原因。补
“隐藏→睡眠→唤醒仍隐藏”和“挂起期间显示/隐藏变化”的 App 接线测试。现有
普通隐藏恢复测试保留。

### CR-P01 / P1：publisher_ref 的必填要求被全局放宽

位置：`petpack/validator.py` 的 `_validate_publishers()`；
[规范第 6.1 节](PETPACK_SPEC_1_0.md)明确 package 必须包含 publisher_ref。

独立复现：合成新包移除 publisher_ref 后仍得到 ACCEPT、无相关警告。对照表却将
规范要求写成“声明则必须解析，缺省合法”。因此“四包全部 ACCEPT”只能证明当前
校验器的结果，不能证明它们符合完整规范。

要求：新包按现有必填规范校验，先逐包明确哪些冻结输入缺字段，再提供版本化的
旧包兼容安排，不能对任意新包默许缺失。不覆盖旧包或盲目改 pin。确需保留历史
包加载时，应提出精确范围、明确诊断、与新作者包分开的方案供主控复核；无需让
用户在两个底层实现方案中先做选择。

### CR-P02 / P1：追加激活事实仍然缺失

位置：`switcher.py` 的 `ActiveSelectionStore` 与激活提交路径；
[规范第 18.10 节](PETPACK_SPEC_1_0.md)要求成功后追加 ACTIVATE_COMMITTED。

代码审阅确认当前选择使用可覆盖的 `INSERT OR REPLACE`；它可证明现在选中了谁，
不能重建此前逐次成功激活的历史。未追加事件是实现缺口，不能改写成命名差异。
按裁定 P-3 实施，测试成功切换、CAS 失败、提交结果不确定和恢复重启；本项是代码
路径审阅结论，不冒充已运行独立崩溃实验。

## 3. 在节点 B 前顺带修正的交付口径

1. **layered idle：** validator 当前为保持 rig fixture 可安装而给出 W002。
   结构层可解析与运行准入应分别测试；不可绘制 idle 不得取得运行准入 ACCEPT。

   迁移到 v2。它验证的是新版本恢复旧备份，不是“该入口恢复后旧程序即可打开”。
   修正报告，提供离线恢复 v1 并启动旧程序的真实演练路径；新版本恢复与降级回滚
   分别命名。无需为此扩大本版 UI 范围。

   生效，应标记未接入。注册表里的音频、TextProfile 等能力须区分格式校验和包内
   运行时消费，补证据或修正宣称，避免 required 检查再次变成假兼容。
4. **报告与公开边界：** “四个在售包”改成“内部保留的四个历史/当前包”；冻结
