## 1. 服务层（`todo/service.py`、`todo/repository.py`）

- **子树归档**：`archive_subtree(task_id) -> int` 在一个事务内归档整棵
  子树，返回受影响数量；不改任何完成状态；聚焦任务在子树内时同一事务
  清焦点。对已部分归档的树重复归档得到一致的全树归档，重复调用返回 0。
  注入中途失败的事务测试证明失败时存储原样（全有或全无）。
- **恢复语义**（一条规则覆盖全部入口）：`restore_archived(task_id) -> int`
  同时恢复目标 + 通往根的**已归档祖先路径** + 目标自己的**已归档子树**，
  完成状态与关系原样保留；恢复根即恢复整棵归档树；恢复单项不会抢占
  焦点。混合归档状态是可见且一致定义的形态。
- **备注专用写入路径**：通用 upsert 不再携带 note 列（消除陈旧缓存覆盖
  长备注的隐患），主树读取不再预加载长备注（工单"主树不预加载所有长
  备注"）；`note_for(task_id)` 按需读取单条备注。超限写入被拒绝、原样
  保留，不静默截断。
- `_UnavailableTodoService` 补齐全部新入口，降级态写入依旧显式失败。

## 2. UI（`ui/panel/todo_page.py`）

- **视图入口**：进行中（默认）/ 已完成 / 已归档 / 四象限四格 / 未分类。
  视图是纯谓词规则，隐藏与归档都不物理删除数据。每个视图标签带实时
  计数，另有"待完成 N"总数——计数与树来自同一次分类扫描，不会互相
  矛盾；完成的父项不计入待完成。
- **主清单隐藏已完成**：未完成子任务继续可见，完成的祖先以淡化
  "（结构路径）"行保留结构上下文（不可编辑、不计入计数）。
- **象限快捷切换**："切换重要/切换紧急"按钮按 未分类→高→低→未分类
  循环，快速改变重要/紧急属性；四象限与时间跨度/期限完全无关。
- **可恢复归档**：物理删除按钮移除，替换为"归档子树"（含 Delete 键）：
  一次操作归档整棵子树、报告影响数量、无确认弹窗；在"已归档"入口
  恢复，恢复后可重新聚焦。
- **备注侧页**：点击任务按需打开。纯文本多段编辑、可见 `N/10000`
  计数、防抖自动保存 + 显式"保存备注"按钮；任务切换与页面关闭前强制
  落盘，切换/关闭不丢未保存内容；写入失败保留草稿并显示原因，修改后
  自动重试。中文长文本、换行与 Emoji 有重启持久化测试。

## 5. 口径修正（第三轮主控返工后）

主控审阅（[V12-05 主控审阅](V1_2_V12_05_CONTROLLER_REVIEW.md)）实测推翻了
上文两条边界声明，修正如下；修复详情见
[第三轮返工集中响应](V1_2_REWORK_ROUND3_RESPONSE.md)：

- "面板页关闭、任务切换都会落盘"不成立：写入失败的草稿在关闭面板时
  随页面一起丢失（CR-U03）。现改为应用级有界草稿存储，面板页销毁后
  草稿仍保留并可重试。
- "恢复后视图一致性由广播与刷新保证"不成立：广播只重建树，不同步
  已打开的备注编辑器，陈旧内容可能被写回覆盖恢复结果（CR-U04）。现
  以存储代数失效编辑器与草稿，并在恢复入口同步树、计数、选择与备注。
