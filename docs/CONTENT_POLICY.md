# RetirementPet 内容、权利与隐私政策

> 文档关系：[文档中心](README.md) · [角色库扩展指南](CHARACTER_LIBRARY_GUIDE.md) ·
> [PetPack 1.0](PETPACK_SPEC_1_0.md) · [当前实施状态](IMPLEMENTATION_STATUS.md)
>
> 版本：1.0 design baseline  
> 状态：FROZEN  
> 适用范围：内置内容、本地 PetPack、未来可选发布流程  
> 性质：产品治理与工程边界，不构成针对具体素材的法律意见

## 1. 目标

本政策解决四个问题：

1. 官方程序可以分发什么；
2. 用户本地可以导入什么，以及界面如何表述；
3. 角色、美术、台词、音乐、配音、商标和真实人物声音如何分别记录；
4. 程序怎样避免借角色包采集或泄露用户信息。

格式校验、hash、签名和安全扫描均不能单独证明内容拥有合法授权。

## 2. 内容通道

通道是 Engine 赋予的受信安装上下文，不是 PetPack 自述字段：

- BUILTIN_OFFICIAL 只能由只读官方发行入口赋值；
- 所有用户文件导入均为 LOCAL_IMPORTED 和 Publisher unverified；
- v2.0 不存在可运行的 COMMUNITY_ONLINE 通道。

包名、publisher_id、显示名称、rights 自述或文件名都不能提升通道。官方验证还必须结合
发行侧权利证据注册表，不能由 manifest 自我证明。

### 2.1 Built-in / Official

官方安装包、官方参考包和未来官方渠道只能包含：

- 项目原创内容；
- 明确取得所需使用与分发授权的内容；
- 已确认处于公有领域的内容；
- 许可证允许当前使用、修改和分发方式的开放内容。

官方随附角色默认不接受 `NC`、`ND`、仅限私人使用或禁止安装包再分发的素材；这些
条件会阻止商业分发、动作修改或正常打包。确有特殊理由时，必须作为新的内容治理
决策明确记录，不能由单个 PR 静默引入。

要求：

- rights basis 不能是 unknown；
- 授权范围必须覆盖实际分发方式；
- 每项素材有可发现的来源、作者、许可和署名；
- 安装包内置角色必须有内部可核查证据；
- 旧版本的权利快照不得被新版本覆盖。

### 2.2 Local Imported

用户可以导入自己制作或收集的 PetPack。rights unknown 可以继续本地安装，但必须显示：

    本地内容
    由包作者或用户自行声明
    RetirementPet 未验证发布者身份或权利状态

本地导入：

- 不上传；
- 不进入官方索引；
- 不自动分享；
- 不自动解析来源 URL；
- 不因格式校验通过而显示为官方、正版或安全认证；
- 风险与声明写入安装 receipt。

本地导入能力不代表任何具体使用当然合法。用户仍需根据素材、用途、地区和传播范围自行确认权利。
允许的 publisher homepage 与 provenance locator 只作为 inert metadata 保存；Runtime、validator、
preview 和面板不得自动 DNS、抓取或预览。资源、动作、音频、布局和模板中的 URL 一律拒绝。

### 2.3 Community / Online

v2.0 不提供公共角色商店。

未来若建设在线渠道，必须先新增：

- 可验证发布者身份和签名；
- 上传与自动扫描；
- 人工审核与风险分级；
- 权利投诉、通知和下架；
- 撤回与恶意包阻断；
- 版本历史与审计；
- 地区和年龄限制；
- 独立法律与隐私复核。

在这些能力完成前，不得把本地导入页面改名为“社区商店”。

## 3. 来源与权利分离

provenance 说明：

- 谁制作；
- 从哪里取得；
- 何时取得；
- 原始作品或素材标题；
- 是否为用户自制、改编或第三方来源。

rights basis 说明：

- original；
- licensed；
- open_license；
- public_domain；
- permission_claimed；
- unknown。

规则：

- user_provided 只能描述来源，不能作为权利依据；
- “网上找到”不是许可；
- “非商业”不自动产生授权；
- “仅本地使用”不自动消除所有权利问题；
- hash 只证明字节一致；
- schema 只证明结构符合规范；
- 数字签名只证明某个密钥签署过内容；
- 以上任何一项都不等于版权授权。

## 4. 第三方角色与系列

Harry Potter、罗小黑等名称在产品讨论中只是用户需求示例。未经许可：

- 官方程序不得预装对应角色、美术、Logo、原作台词、配乐或配音；
- 官方不得抓取、代下载或提供搜索结果直链；
- 官方不得将第三方名称作为内置“已支持系列”营销；
- 本地包显示名称来自该包，并同时显示发布者和来源声明；
- UI 不得暗示第三方权利人与 RetirementPet 存在合作。

系列名、角色名、Logo、美术、台词、音乐和声音可能涉及不同权利，必须分别判断，不能用一项授权覆盖所有素材。

## 5. 逐资产治理

每个媒体资产必须指向：

- source_ref；
- rights_ref；
- creator 或 claimant；
- license 或自定义许可；
- claimed scope；
- attribution；
- 必要时的 content warning。

混合许可包：

- 必须逐资产记录；
- 不能用一个虚假的统一 license 覆盖；
- 无法确认时标为 unknown；
- official 通道不得接收 unknown；
- 本地通道必须醒目标记。

自定义许可文件只能作为纯文本 legal file，不能执行，也不能自动打开其中链接。

## 6. 改编、同人和原作素材

角色包可能同时涉及：

- 原角色设定；
- 新绘制的同人美术；
- 原作截图或剧照；
- 原作逐字台词；
- 字体与 Logo；
- 原作音乐或录音；
- 配音演员或真人声音；
- 包作者新增的动作与文案。

一项内容是“包作者自己画的”不当然意味着原角色权利已经解决；反过来，获得角色视觉授权也不当然覆盖音乐、录音、台词、表演者声音或商标。

引擎只记录声明和来源，不自行裁决复杂的合理使用、戏仿、引用或地区性例外。

## 7. 个人本地使用与公开传播

中国著作权法列出复制、发行、改编和信息网络传播等权利，并规定个人学习、研究或欣赏等有限情形；这些例外仍有作品已发表、署名、不得影响正常使用或不合理损害权利人利益等条件。

产品因此采用：

- 本地私人导入：允许 unknown 但警示；
- 私人备份：允许导出为明确标记的私人备份；
- 发布或分享：必须填写逐资产来源与权利声明；
- 官方分发：必须具有可核查权利基础。

免责声明不能替代授权，也不能把公开传播重新定义为私人使用。

参考：

- 中华人民共和国著作权法：https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html
- 信息网络传播权保护条例：https://xzfg.moj.gov.cn/front/law/detail?LawID=167
- 中华人民共和国商标法：https://www.cnipa.gov.cn/art/2019/7/30/art_95_28179.html

## 8. 台词与文案

- 用户文案和角色推荐文案必须分开保存；
- 原作逐字台词需要独立 source 和 rights；
- 包升级不能静默替换用户 TextProfile；
- 文案只按纯文本渲染；
- 禁止富文本、脚本、自动链接和伪装系统安全提示；
- 模板变量只来自 Engine allowlist；
- 包不能通过文案读取按键、窗口、路径、剪贴板或网络内容；
- 超长文本、控制符和双向控制符必须验证。

当角色缺少工作或会议动作时，Engine 可以显示自己的通用语义提示；不得复制另一角色台词。

## 9. 音乐、音效、配音与声音

四类内容分开治理：

- 用户音乐库：用户主动选择的本地长音乐，不打包进 PetPack；
- 角色短音效：受时长和总量限制，逐资产声明；
- 原作配乐和录音：需要覆盖复制与分发的权利依据；
- 模仿或克隆真人声音：除版权和录音权外，还可能涉及人格权益。

默认预览静音。会议和勿扰 Context 可以禁止角色自动发声。包不能通过“角色音效”携带无限长音乐。

关于自然人肖像和声音保护，可参考全国人大关于民法典人格权编的说明：

https://www.npc.gov.cn/npc/c2/c30834/202009/t20200928_307898.html

## 10. 商标与混淆

角色包的显示名称不等于 RetirementPet 对该名称的认可。

官方 UI 必须区分：

- Official built-in；
- Local imported；
- Publisher declared；
- Publisher unverified。

本地包不得使用 Engine 保留的 official 命名空间。包作者声明、格式验证和 hash 不得显示成“官方授权”。

## 11. 安装与升级界面

安装前至少显示：

- 包名、系列、角色数量；
- 声明发布者；
- 来源状态；
- rights basis；
- license 与 attribution；
- unknown 或混合许可警示；
- 内容警示；
- 压缩和安装后体积；
- 动作与音频能力；
- Engine 兼容性；
- archive hash 前缀；
- 是否可以本地回滚。

升级还必须显示 diff：

- 发布者声明；
- rights、license、scope 和 attribution；
- 新增或删除角色；
- 新增或删除动作；
- 新增格式或能力；
- 资源体积和警示；
- 签名状态。

用户确认过的 warning code 写入 receipt，但不把 warning 变成已验证事实。

## 12. 分享、发布与备份

界面必须区分：

### 私人备份

- 目标是恢复自己的本地内容；
- 明确标记 private backup；
- 不暗示可公开再分发；
- 保留原 rights/source metadata。

### 本地导出与发布者声明包

- v2.0 的普通 local export 可以保留 unknown，但必须继续醒目标为本地、权利未验证，不能使用“可发布”措辞；
- 使用“发布者声明包”措辞时，要求每项资产 rights basis 非 unknown，scope_claimed 包含 redistribution；
- 用户必须显式声明其具有分发权；
- 生成 attribution；
- 阻止 official namespace 冒用；
- 即使字段完整，也只能显示“发布者声明完整”，不得显示“分发合法”或“已授权”；
- official pipeline 另有外部可核查证据 gate；
- 未来在线发布还需要签名和审核。

不能用“导出成功”表示“发布合法”。

## 13. 隐私边界

RetirementPet v2.0 默认：

- 无遥测；
- 无自动联网；
- 无来源 URL 探测；
- 无云账户；
- 无广告；
- 无自动上传；
- 无崩溃 dump 上传。

PetPack 永远不能请求：

- 网络；
- 麦克风；
- 摄像头；
- 剪贴板；
- 活动窗口标题；
- 屏幕截图；
- 文件系统任意读取；
- 注册表；
- 原始键盘内容；
- 鼠标轨迹历史。

键鼠联动只使用系统提供的 idle duration 或 active / idle 等聚合信号。程序不得保存具体按键和值。

未来联网模块必须：

- 独立于 PetPack；
- 默认关闭；
- 由用户显式安装或启用；
- 单独说明数据、目的、保留期和撤回方式；
- 不改变 v2.0 本地核心的默认离线承诺。

## 14. 日志与诊断

普通运行日志可以记录：

- 稳定 diagnostic code；
- 操作阶段；
- 包内部 ID；
- package version；
- hash 前缀；
- 成功、降级、回滚或失败；
- 性能 marker。

普通日志禁止记录：

- 具体按键；
- 窗口标题；
- 剪贴板；
- 屏幕内容；
- 用户自定义台词全文；
- 完整 manifest；
- 原始音乐库；
- URL query、token 或凭据；
- 源归档绝对路径；
- 其他包含用户名或私人目录的非必要路径。

默认：

- 日志总量目标 10 MiB，上限 20 MiB；
- 保留期目标 7 至 14 天，最终数值随性能预算冻结；
- 用户可查看和一键删除普通日志；
- 安装 receipt 与短期日志分离；
- receipt 默认不保存源绝对路径；
- receipt 的 source/rights snapshot 禁止本地绝对路径、URI userinfo、凭据和 secret-like query；
- 需要 query 的公开 locator 只保存规范化脱敏形式与原声明 hash；
- 崩溃 dump 若可能包含内存，默认关闭或单独同意。

## 15. 内容警示

包可以声明：

- 闪烁；
- 突发声音；
- 成人或敏感主题；
- 本地未验证内容；
- 其他 Engine allowlist 项。

引擎仍必须独立验证：

- FPS；
- 闪烁频率；
- 音量策略；
- 自动播放；
- 图片与音频资源预算。

作者警示不能替代技术限制。

## 16. 删除与保留

UNINSTALL_REVISION 删除一个精确 revision；UNINSTALL_PACKAGE 是 UI 明列所有受影响 revisions 的
受控批处理，角色和 Variant 不是独立安装单元。活动、pinned 或 last-known-good revision 必须先完成
安全切换和替代健康 checkpoint。

卸载默认：

- 删除应用托管的包修订版；
- 删除该版本派生缓存；
- 不删除用户选择的原始 .petpack；
- 不删除用户文案、行为覆盖和个人素材；
- 不删除退休倒计时和其他全局数据；
- 保留不可变 rights/source receipt 与生命周期 tombstone。

用户可以另行选择永久删除角色个人配置或普通日志。每种删除范围必须单独列出大小并确认。

如果用户要求删除历史 receipt，应明确这会降低本地追溯能力，并作为独立的数据清理操作处理。

## 17. UI 措辞

允许：

- 格式已验证；
- 文件 hash 一致；
- 本地导入；
- 包作者声明；
- 发布者未验证；
- 权利依据 unknown；
- 官方内置；
- 已回滚到上一健康版本。

禁止在没有相应证据时使用：

- 安全包；
- 正版；
- 官方授权；
- 已认证作者；
- 无版权风险；
- 因 hash 通过而可信。

## 18. 官方参考角色

内置退休猫必须：

- 为原创或有完整可核查权利；
- 作为普通 PetPack 1.0 通过相同 schema 和 Runtime 接口；
- 在包损坏、配置损坏和安全模式下可恢复；
- 不可由用户卸载；
- 不依赖网络或用户外部素材；
- 不绕过资源预算，只允许在可信分发和权利门槛上标记 official。

## 19. 政策验收

发布前必须证明：

- official 包无 unknown rights；
- 混合许可逐资产可发现；
- 本地 unknown 的安装警示醒目且准确；
- rights 变化升级显示 diff；
- UI 不把 hash/schema 当授权；
- 默认流量抓包为零；
- 日志 canary 不出现按键、窗口、台词、URL token 和绝对路径；
- PetPack 不能请求被禁止能力；
- 卸载不删除用户原始归档和全局数据；
- 第三方角色示例没有被打入官方发行包。

任何一项失败都属于发布阻断，不得用免责声明代替修复。
