本工单将现有 R1、R2、R3、R5 和面板、验收技术债组织成一个可连续实施的版本。
目标是让桌宠能正常播放角色动画、以正确比例显示，并让本地 Todo 和配置具备日常
使用所需的完整流程。应用目标版本建议为 **1.2.0**，发布定位继续是可回滚 Alpha；
版本号在候选收敛时统一更新。PetPack schema 仍为 1.0，Todo schema 目标为 2，
半写实猫内容目标为 0.2.0，这几条版本轴分别管理。

本文是执行需求与建议验收口径，不是已完成证明，也不自动修改冻结规范。标为
“建议”的产品细节可由执行者提出更好的方案；涉及冻结含义的变化交主控裁定，
普通接口设计、文件拆分、控件选择、错误处理和测试组织由执行者自行完成。

## 1. 工作方式与交付边界

本地模型负责调查、设计、编码、关联重构、测试、文档和交付报告。Codex 负责范围
协调、检查真实 diff、独立复现关键验收、提出返工项和给出最终结论。用户负责分配
执行模型、提供美术与真实设备条件，以及决定发布。无需每完成一个函数就请求确认。

执行者可以调整模块内部顺序、增加必要文件、修复发现的关联缺陷。先读现有实现，
复用已有配置、生命周期和测试设施；避免为本次功能另起一套平行框架。工作超出
本工单目标时，记录影响并继续其余工作；有具体方案的重大取舍再交主控处理。

开始时记录实际 HEAD、分支、工作树状态、Python/Qt 版本和相关测试基线。内部
运行身份留在私有交付记录中。本地开发使用独立功能分支，建议 `codex/v1.2-daily-use`；
已有用户改动须保留。可做逻辑清楚的本地提交，不要求一次完成一个巨大提交。
若用户另分配多个执行者，使用独立工作树并约定集成负责人，避免同时写同一工作树。

必要边界只有以下几项：

- 默认使用隔离的测试数据目录与合成任务，不修改当前日用数据库。真实数据迁移
  是最终试用动作，由用户确认后进行；测试、日志和仓库中不得出现个人任务与备注。
- 保留冻结包、旧 receipt、历史 evidence 和私有开发历史；新内容使用新 Revision。
- 继续使用 Python/PySide6 与离线 PNG PetPack；不引入云同步、联网商店或实时 3D。
- 本单授权本地开发与候选准备。公开同步走“内部仓库 → 脱敏快照 → 公共仓库功能
  分支 → PR → CI/审核 → main”；发布由主控和用户安排，不给内部仓库直接加远端推送。

## 3. V12-01：正常播放动画，并真正使用角色几何

**现状与目的。** 应用 `_compose_snapshot()` 在 `controller.current` 为空时将
`elapsed_ms` 写成 0，Runtime 虽支持 sequence，正常 idle 仍停在首帧。正文绘制
主要按整张 PNG 适配窗口，未消费 manifest geometry。

**需求。**

1. 建立基于单调时钟、语义清楚的 idle 时间轴。明确进入 idle、动作结束、角色切换、
   隐藏恢复和睡眠唤醒时是续播还是重置；选择合理默认并落实测试。系统日期调整
   不应导致动画倒退；恢复时不补跑大量历史帧，也不改变既有动作时长语义。
2. 让 logical_canvas、content_bounds、motion_bounds、reference_height、base_anchor、
   bubble_anchor 和 hit_regions 参与实际布局。正文、气泡、点击区使用一致变换，
   保持等比缩放；区分逻辑坐标、窗口 DIP 与设备像素。
3. 按动作整体运动边界安排空间，避免按单帧 Alpha 边界反复缩放导致呼吸般大小跳动。
   布局切换、面板展开、角色切换和跨 DPI 时脚底位置保持稳定，边缘夹紧时允许
   有依据的整体位移；透明留白不应形成不必要的桌面点击遮挡。
4. 兼顾现有官方、半写实静态包和 Bootstrap 安全显示。可选动作缺失时仍回退到当前
   角色 idle；首帧预检、切换失败恢复与正常播放共用一致的显示含义。

**验收。** 合成至少三帧、颜色/形状可区分且帧时长不同的包，通过真实 App 快照
到 Runtime 绘制证明跨帧、循环边界及动作返回 idle 都正确，不能只给 Runtime 手填
时间。覆盖方形、竖图、宽图、大留白及 DPR 1.0/1.5/2.0；验证绘制结果、脚底、
气泡与点击区。建议结构测试允许最多 1 DIP 舍入误差，采用其他容差须说明依据。
结构模拟不等同于真实混合 DPI 验收。

**代码入口。** `app.py`、`petpack/runtime.py`、`ui/pet_window.py`、
`layout_policy.py`；参考 `test_app_smoke.py`、`test_petpack_runtime.py`、
`test_layout_policy.py`、`test_window.py`。

## 4. V12-02：补齐本版实际依赖的 PetPack 一致性

**需求。** 对照 [PetPack 规范](PETPACK_SPEC_1_0.md)，列出本版涉及字段的
“规范要求 → validator → GUI preflight → Runtime”对照表，并修复闭环：

- geometry 的有限数值、尺寸、边界、锚点、reference_height 与 hit region；
- compatibility 与必需/可选 capability 的接受、降级、拒绝语义；
- publisher_ref、legal_files、rights/source、动作与资源引用闭包；
- 本版启用的 TextProfile、推荐配置和安全变量边界；
- 激活成功确实记录 `ACTIVATE_COMMITTED`，失败不误提交活动选择。

先审计冻结官方包和当前 0.1.1：严格化验证可能让现有包失效。提供逐包结果及兼容
方案；不能为了让旧包过关而全局跳过校验，也不能覆盖旧包补字段。需要调整冻结
规范或发行新官方 Revision 时，写出具体差异和影响供主控处理，继续无关模块。
未形成运行时支持的能力，不因 validator 能解析就写成已支持。

**验收。** 合法、缺必填、错误类型、NaN/无穷或非法尺寸、悬空引用、未知 required
能力、损坏或不匹配 legal 文件等 fixture 得到稳定结果。拒绝后活动角色与安装
事实不被错误改变；当前可用包仍能安装、激活或得到明确的版本化兼容安排。新增
fixture 与诊断码有可追溯含义，不通过批量改预期值掩盖回归。

**代码入口。** `petpack/validator.py`、`manifest.py`、`local_import.py`、
`switcher.py`、`lifecycle.py` 及对应 PetPack、切换、生命周期测试。

## 5. V12-03：作者工具从骨架补齐为完整工作流

**需求。**

1. `init` 生成可直接构建并通过 validate/preflight 的最小原创静态包，包含可用
   透明图、geometry、idle、缩略图及来源许可声明。测试模板无需外部下载。
2. 增加可操作的 lint、动作接触图、帧数/总时长/解码预算报告、画布与锚点检查。
   静态图与 sequence 都能预览；预览复用实际 Runtime，不改变活动角色、Context、
   用户配置或用户库，也不发声。
3. 修复 ZIP 成员实际未压缩的问题，保持确定性构建；对官方与 canonical 示例的
   冻结输出实行一致的防覆盖保护。区分 archive hash 与 content digest，明确
   哪类变化需要新 Revision，不改旧 pin 来迁就新输出。
4. 写清“模板 → 编辑 → lint → build → validate → preflight → preview → GUI 导入”
   的命令与错误排查。`install-local` 不作为本版必交，现有 GUI 导入足以闭环；
   如实现 CLI 安装，须复用正式确认与生命周期流程。

**验收。** 在空测试目录从 init 走完流程；相同输入在两个独立输出位置得到逐字节
相同包；检查实际压缩类型、透明度与预算。错误输入得到可读诊断；源工程中的
不支持文件不能悄悄混入有效发行包。GUI 能导入新包并由用户选择启用。

**代码入口。** `scripts/petpack_cli.py`、`petpack/`、`test_petpack_cli.py`、
`test_character_onboarding.py` 与[角色库扩展指南](CHARACTER_LIBRARY_GUIDE.md)。

## 6. V12-04：Todo schema v2、备份与恢复

**需求。**

1. 设计显式 v1 → v2 迁移，承载独立的重要/紧急维度、可恢复归档、纯文本长备注。
   字段名和表结构由执行者设计；兼容 domain、repository、service 和 UI 的完整链路。
2. 旧任务 ID、父子关系、排序、时间跨度、状态、日期和有效焦点保持不变。旧任务
   默认“未分类”、备注为空；不根据标题或期限猜测重要性，不在迁移中批量改变完成状态。
3. 写入 v2 前完成一致且可验证的备份，涵盖 SQLite journal/WAL 的现实情况。
   可以采用 SQLite 备份 API 或经过证明的关闭连接复制流程，不裸拷贝正在写入的主文件。
4. 迁移具有事务性和中断恢复策略，成功后校验 schema、数据完整性与外键。备份失败
   则不开始迁移；中途失败保持旧库可恢复，不把坏库/空库误当成全新用户而重建。
5. 未知、更高版本、损坏库、锁冲突、磁盘写入失败都保留原数据并给出可操作提示。
   Todo 不可用不应让桌宠整体崩溃，也不能显示一份假装保存成功的临时清单。
6. 提供迁移前自动备份和显式备份/恢复入口，记录 schema 与备份时间，并制定有上限
   的保留策略。保留可用的迁移前副本；自动清理只处理应用管理的备份。
   恢复先保全当前库，关闭旧连接并验证恢复对象，失败不覆盖唯一可用数据。
7. 说明旧程序不能直接读写 v2；回滚应用须配套恢复兼容数据。区分“恢复迁移失败”
   与“回到旧版”，并提示后者不会包含备份之后新增的任务。

**验收。** 使用含中文、Emoji、多层树、完成/未完成、日期与焦点的合成 v1 fixture，
对比迁移前后字段。覆盖首次新建 v2、重复打开、备份失败、迁移中断、提交边界失败、
恢复失败、新版本库拒写和 journal/WAL 场景；在隔离目录演练旧版配套恢复。
检查 `quick_check` 与 `foreign_key_check`，不能仅确认表中多了几个字段。

**代码入口。** `todo/migrations.py`、`repository.py`、`domain.py`、`service.py`、
`errors.py`、`test_todo.py`；复用现有 fail-closed 文件族检查，不整体删掉安全路径。

## 7. V12-05：四象限、可恢复归档与长备注

**需求与默认产品口径。**

- 保留短期/中期/长期与原有子任务树；新增独立四象限视图或筛选入口，能快速改变
  重要/紧急属性，并保留“未分类”入口。不把四象限强行映射成时间跨度或期限。
- 默认主清单隐藏已完成任务，提供已完成/归档入口并可恢复。自动隐藏是视图规则，
  显式归档是可逆操作，两者均不物理删除数据。
- 父子完成状态继续独立。完成父任务不会完成或隐藏其未完成子任务；建议保留淡化
  的祖先路径作为结构上下文，父项不计入未完成数量。完成项虽在主清单隐藏，仍可
  在已完成入口看到；迁移后的旧完成项适用同样规则。
- 显式归档父任务时按既有子树约束以一个事务归档整棵树，说明影响数量，不改变
  子孙完成状态。恢复整棵归档树保持原状态和关系；恢复单项遇到归档祖先时，建议
  同时恢复必要祖先路径。混合已归档子树的重复归档/恢复也要定义一致行为。
- 完成或归档当前焦点任务时清除焦点；恢复任务不自动抢占焦点。计数、四象限、
  树视图与运行时焦点投影一致；个人标题与备注仍不进入角色 Context/气泡。
- 点击任务可打开按需创建的备注侧页，支持多段中文纯文本、滚动、保存反馈与重启
  持久化。建议以一万汉字加换行/Emoji 作为验收样本；限制需可见且不能静默截断。
  明确自动保存或显式保存策略，任务切换/关闭时不丢未保存内容；写入失败能保留草稿
  并重试。主树不预加载所有长备注。

这些默认交互可由执行者优化，但须保留“未完成任务可找到、层级不丢、操作可恢复、
反馈与落盘一致”的结果。优先把正常操作做顺畅，不增加无意义的确认弹窗。

**验收。** 从 UI 创建树、设象限、写长备注、切换页面、重启、完成父项、归档子树、
恢复、重新聚焦，逐步核对数据库及视图。覆盖失败反馈、空列表、混合状态子树和
筛选下的编辑；备份后恢复也能回到一致视图。保持单焦点、深度上限、无环约束及
全局快捷键入口，关闭面板后不遗留备注轮询或大批数据常驻。

**代码入口。** `ui/panel/todo_page.py`、`todo/service.py`、`context_bridge.py`、
`test_todo.py`、`test_control_panel.py`、`test_global_hotkey.py`。

## 8. V12-06：让配置页面真正保存并生效

**需求。**

1. 五种既有布局与命名可见性预设按引擎允许矩阵保存、应用、重启恢复；不是只把
   下拉框从禁用改为启用。正文、倒计时、气泡与装饰均按有效配置显示。
2. 文案支持选择或编辑纯文本模板、预览、应用、恢复默认。沿用安全变量白名单，
   未知变量按已有约定处理；支持全局与角色覆盖，并让用户理解当前设置作用范围。
3. 动作页实时反映当前行为，并在动作能力范围内提供手动触发、自动/禁用及支持时
   的循环控制。缺失素材清楚显示回退情况；不绕开会议、勿扰、静音和冷却规则。
   本版围绕核心动作，不要求实现所有发布者专属动作。
4. 沿用 EffectiveConfigResolver 的优先级，包推荐仅在用户明确应用后生效。非法
   配置或保存失败保留上次有效值，控件反馈与实际行为一致；角色切换不覆盖全局设置。
5. 面板与预览按需工作，关闭后释放资源；鼠标穿透、置顶、托盘恢复、单一正式角色
   和窗口不抢焦点的现有行为保持有效。

**验收。** 每项执行“修改 → 应用 → 实际显示/动作改变 → 重启保持 → 恢复默认”；
测试允许矩阵、角色覆盖、配置写失败、坏配置和长中文模板。包含真实 UI 与 App
接线测试，不只验证 resolver 返回值。勿扰下被禁动作不能通过新按钮绕过限制。

**代码入口。** `ui/panel/pages.py`、`config_system.py`、`settings.py`、

## 9. V12-07：角色库版本详情、安全卸载与回滚

## 14. 统一验证方法

先运行受改动影响的测试，关键节点再跑完整回归。以下是现有基础命令，测试新增后
由执行者补进对应套件；不要求机械复制固定测试数量。

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.venv\Scripts\python.exe -I -B -m pytest -p no:cacheprovider tests
git diff --check
```

原生窗口验证使用单独进程和测试数据目录，清除 offscreen 设置再执行：

```powershell
Remove-Item Env:QT_QPA_PLATFORM -ErrorAction SilentlyContinue
$env:RP_RUN_NATIVE = "1"
.venv\Scripts\python.exe -I -B -m pytest -p no:cacheprovider tests\native -q
```

测试 fixture 中的原生自启检查不等于真实注销/登录。公开快照检查也不是直接对内部
工作树执行 `--verify-public-tree`；该命令用于已经导出的公开 HEAD。导出和候选
构建按现有脚本与 receipt 流程执行，报告命令、工作目录类别和被测身份。

V12-E1 保留六项真实门禁：100/150/200% 混合 DPI 与负坐标/拔屏；真实登录自启；
锁屏、会话断开与睡眠唤醒；无 Python/Anaconda 且有竞争 Qt PATH 的干净 Windows 11
VM；同一候选 24 小时稳定性；三台参考设备的性能样本及预算冻结。没有环境时准备
工具和操作说明并如实记 SKIP，不要求执行模型凭空完成。
