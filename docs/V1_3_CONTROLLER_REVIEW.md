## 必须返工

### CR13-01（P0）Markdown 预览仍可读取本地文件

`sanitize_preview_markdown()` 只移除 `![alt](url)` 内联图片。引用式 Markdown：

```markdown
![secret][local]
[local]: <file:///private/secret.png>
```

会绕过正则并由 Qt 文档层读取。独立像素探针用 24×24 纯色本地 PNG 复现出
576 个目标色像素，证明不是理论风险。

验收要求：

1. 禁止所有图片语法实际加载资源，包括引用式、折叠式、快捷引用、相对路径、
   `file:`、`data:`、网络 URL，以及 Qt 支持时的原始 HTML `<img>`。
2. 不以单个正则枚举 URL 变体作为安全边界；应在送入 Qt 前解析/剥除全部图片节点，
   或让实际文档资源加载入口 fail-closed。
3. 增加真实临时图片和像素级反例；每种语法均断言文件未被读取且预览无目标像素。

### CR13-02（P1）本地 Agent 端点未落实同用户访问边界

Agent 协议复用 `QLocalServer`，当前服务创建后直接 `listen()`，实测
`socketOptions()` 为 `NoOptions`。用户名参与服务器命名只解决命名冲突，不构成授权。

验收要求：

1. 在 `listen()` 前设置 `QLocalServer.UserAccessOption`，失败时 fail-closed，不能退化为
   无鉴权服务。
2. 测试实际服务器选项；Windows 可行时补不同用户/SID 无法连接的边界证据。
3. 文档把安全边界写成实际实施的 ACL/用户范围，不能仅写“按用户名命名”。

### CR13-03（P1）幂等缓存会错配请求，并吞掉参数冲突

缓存键只有 `operation:idempotency_key`，缓存值包含首个完整响应。相同 key、不同参数、
不同 `request_id` 的第二次请求会返回首次成功结果，并回带旧 `request_id`。这同时违反
“响应原样回带当前 request_id”和幂等键不得代表两个不同写操作的基本约束。现有测试
用 `first == second` 固化了错误行为。

验收要求：

1. 缓存同时保存规范化请求指纹与业务结果；同 key + 不同 operation/args/并发前置条件
   返回 `CONFLICT`，且不执行第二次写入。
2. 同一请求重试只复用业务结果，响应必须绑定本次 `request_id`；如决定强制同一
   `request_id`，协议、CLI 和测试必须一致明确，不能悄悄返回旧关联号。
3. 增加真实 socket 线级测试：同 key 同参数不同 request_id、同 key 不同参数、并发
   前置条件改变三种情况。

### CR13-04（P1）公开快照结论已失效，罗小黑边界未进入策略

当前 HEAD 导出因节点 C 报告中的盘符绝对路径样式被拒绝。另有
`scripts/build_xiaohei_local.py` 被 Git 跟踪，但 `config/public_snapshot.json` 未排除它。
用户已经裁定罗小黑相关内容保持本地通道，公开策略必须把该裁定变成可执行规则。

验收要求：

1. 文档改用机器无关占位写法，重新从**返工后的同一 HEAD**导出并取得 ACCEPTED。
2. 明确罗小黑本地构建脚本是否属于公开范围；按当前裁定应从公开快照排除，并以测试
   固化“包、原图、衍生图、截图、构建产物及专用构建脚本不出现”。
3. 在新快照中从零运行治理与测试；报告记录新 HEAD、导出审计和结果，旧结果保留为历史。

### CR13-05（P1）SBOM/许可材料尚不具备公开二进制发布条件

`generate_release_materials.py` 没有专项测试，并把数行摘要写成“完整许可文本”。独立对
最终 dist 生成材料后，Python、应用和资产版本出现 `null`；根因包括只读取
`build_lock.json` 的 `packages` 子对象、receipt 没有顶层 version。当前归因还把
OpenSSL DLL 归入 Python、把 FFmpeg DLL 归入 PySide6，未提供 OpenSSL/FFmpeg 的独立
许可与 notice；PyInstaller 许可文件会无条件生成，但组件汇总未证明 bootloader 已归因。

验收要求：

1. 随包放入实际完整许可文本和必要版权 notice，不得用链接/摘要冒充全文。
2. 显式识别 Qt/PySide6、FFmpeg、OpenSSL、Python、WinRT、PyInstaller、应用和随包资产；
   版本不得为 `null`，归因规则要覆盖最终 onedir 的真实文件。
3. 用合成目录测试未知 DLL fail-closed、版本来源、组件规则与完整文本；再对最终候选做
   逐文件审计。
4. 冻结材料与 receipt 的关系：若材料属于下载目录，必须在最终 manifest/receipt 之前
   生成；若单独分发，则生成独立、绑定同一候选身份的 receipt。不能验收后修改 dist。

### CR13-06（P1）最终候选与报告/门禁身份未闭环

节点 C 报告仍记录 `2cc0269` 候选，当前产物与 receipt 对应 `ac6f1eb`；最终 release
目录中未发现该候选的 `acceptance.json`。因此当前只有“构建身份可核对”，没有
“最终候选通过 Alpha 门禁”的证据。

验收要求：完成 CR13-01 至 CR13-05 后冻结新 HEAD，一次性生成候选、发布材料、receipt，
再对同一字节运行 Alpha 门禁。报告只引用这一个最终身份；热键若仍受环境限制，状态继续
保持 NO-GO，不得以旧候选或源代码测试替代。

### CR13-07（P1）开发流程曾终止用户正在使用的旧候选

执行记录明确写到为了重建 dist，终止了仍在运行的旧 1.2.0 `RetirementPet.exe`。这违反
“开发过程不影响日常使用”的隔离承诺。构建系统遇到用户进程占用产物时应失败并提示，
不能清理不属于本次 harness 的进程。

验收要求：

1. 构建、smoke、门禁使用独立候选目录、独立数据目录和唯一实例名。
2. 只允许终止由本次运行启动且能以进程句柄/父进程/receipt 证明归属的进程。
3. 加反例：外部已运行桌宠占用旧 dist 时，构建明确失败或换新目录继续；外部进程保持存活。

## 应当修正但不阻塞节点 B 功能复验

- 媒体命令当前在 Qt 调用线程执行 `future.result(timeout=5)`；无响应播放器可让 UI/Agent
  请求卡住 5 秒。改为异步完成或短时非阻塞状态机，并测试 provider 永不返回的情形。
- `set_app_active(False)` 只丢弃回调，provider worker 仍保持订阅/扫描。若“隐藏/挂起暂停”
  是资源承诺，应暂停 provider 工作并在恢复时重新同步，而不是只暂停投影。
- 单实例连接异常路径调用 `waitForBytesWritten(1000)`，恶意/异常客户端可让 UI 线程阻塞；
  改为异步断连或更严格的无等待失败路径。

## 复验顺序

1. 先修 CR13-01、CR13-02、CR13-03、CR13-07，复验节点 B 的安全与协议边界。
2. 再修 CR13-04、CR13-05，重新生成当前 HEAD 的公开快照与发布材料。
3. 最后执行 CR13-06：冻结 HEAD，重建唯一候选并运行绑定门禁。
4. 返工报告必须逐项给出原反例的新结果；新增测试总数只能作为辅助信息。

在上述条件完成前，当前版本可继续内部开发和日常试用，但不得公开同步或发布 1.3.0
二进制。
