## 裁定

当前角色内容分为三类，发布边界如下。

| 内容 | 仓库现状 | 公开源码快照 | 官方二进制 | 下游复用 |
|---|---|---|---|---|
| 官方退休猫 | 项目原创程序化素材；包内保留所有权利并允许随 RetirementPet 再分发 | 允许 | 允许 | 只按包内许可；根 MIT 不覆盖 |
| 半写实退休猫 0.1.1 | AI 辅助原创原型，有完整 provenance 和项目范围许可 | 允许，必须同时保留 provenance | 允许 | 只按包内许可；根 MIT 不覆盖 |
| 半写实退休猫 0.1.0 | 像素与 0.1.1 相同，但保留不适合公开的旧 PNG 元数据 | 禁止，继续精确排除 | 不作为新发行内容 | 仅保留内部审计事实 |
| 尚未入库的原创幼猫等素材 | 当前 Git 跟踪树中没有对应媒体，尚不能逐文件核验 | 完成来源、作者和项目分发授权记录后允许 | 经新 PetPack 验收后允许 | 依届时选定的资产许可 |
| 罗小黑及其他无可核查授权的第三方 IP | 当前 Git 跟踪树中没有对应媒体或角色包；只存在政策文字和本地素材规划 | 禁止 | 禁止 | 仅允许用户自行本地导入并承担许可判断 |

项目所有者已确认当前仓库中的官方退休猫和半写实退休猫继续沿用原有发布方式。
本次不把这些角色换成 CC0、CC BY、MIT 或其他开放内容许可证，也不修改已有
PetPack Revision 的许可文本、摘要或权利快照。

“允许项目发布”不等于“任何人可把角色素材取出后自由修改、商用或放入其他项目”。
公开仓库的根 MIT 只覆盖其声明范围内的代码、文档和映射为 MIT 的原创资产；角色
媒体的接收者只能依照包内许可行事。如果未来希望给予公众更宽的复用权，必须由
权利人另行明确授权，并发布新的 Revision，不能回写旧包。

## 罗小黑与其他第三方 IP 的执行规则

未经能够覆盖实际发行方式的书面许可，不得：

- 把角色图片、模型、动画、Logo、台词、音乐、配音或其 PetPack 提交到仓库；
- 随官方安装包、公开快照、Release 附件、示例素材或宣传截图分发；
- 由应用搜索、抓取、代下载或将其标记为“官方”“正版”“已授权”；
- 用“同人”“非商业”“学习用途”、AI 重绘、hash 或 manifest 合规替代授权。

允许的边界是用户从自己的本地文件主动导入，应用按 `LOCAL_IMPORTED` 与真实
rights/source 声明展示。此类文件留在应用私有数据目录，不进入 Git、构建输入、
公开快照或诊断证据。

## 发布检查

每次公开快照或二进制组装必须确认：

1. Git 跟踪媒体清单没有新增未裁定的第三方角色内容；
2. 0.1.0 仍由 `config/public_snapshot.json` 精确排除；
3. 0.1.1 的包内许可和 `realistic-retirement-cat.PROVENANCE.md` 同时存在；
4. 官方退休猫的包内许可随包保留，且没有被根 MIT 错误覆盖；
5. 第三方组件 SBOM、NOTICE 和 LGPL 材料另行完成，不能用本裁定替代。

当前裁定允许继续准备公开快照，但不解除二进制第三方组件许可材料的 NO-GO。
