### CR-U01：已完成归档项的恢复按钮不可用

位置：`ui/panel/todo_page.py::_update_action_states()`，审阅时第 835–836 行。
当前表达式 `(is_done or is_archived) and not (is_done and is_archived)`
在两者均为真时禁用恢复，但 `_on_restore()` 已有按 archived 优先恢复的逻辑。

复现：创建独立任务 → 完成 → 归档 → 已归档视图 → 选择它。恢复按钮 disabled；
点击无效果，数据库仍为 `status=done, archived=True`。没有可用的祖先根可以
间接恢复时，该任务无法由用户恢复。

要求：所有归档任务都能解除归档，同时保留原完成状态；已完成未归档任务可恢复
为未完成。测试未完成/已完成 × 未归档/归档，并覆盖已完成根、叶子和混合子树，
必须经真实按钮完成流程，不能只直接调用服务。

### CR-U02：备注读取失败后跨任务覆盖

位置：`TodoPage::_open_note_for()` / `_load_note()`，第 719–759 行。

合成任务 A、B 分别存有 `A original`、`B original`。先选择 A，再仅让 B 的
note_for 抛 TodoError，选择 B。当前选择和 `_note_task_id` 都是 B，编辑器
却仍显示 A 的内容。追加 ` edited` 并保存后，B 数据库变成
`A original edited`，界面显示“备注已保存”。这是可复现的数据覆盖。

要求：加载状态、编辑缓冲和任务 ID 必须一起切换。读取失败时展示明确失败状态，
保留原任务草稿但不得把它作为新任务内容；新任务内容读取成功前阻止保存。
验证 TodoError、存储不可用和一般读异常；解除故障后能重试，A/B 数据均正确。

### CR-U03：切换后保留的失败草稿在关面板时消失

位置：`TodoPage::_flush_all_drafts()` / `deactivate()` / `dispose()`，以及
`ControlPanel::_dispose()`；第 802–805 行的 flush_all 实际只调用 _flush_note。

复现：A 原存 `A persisted`；编辑为 `A unsaved draft`，仅令 A 写入暂时失败，
切到 B。此时 `_drafts[A]` 存在。解除写入故障后关闭面板，再重开选择 A：数据库
和编辑器均只有 `A persisted`，草稿不再存在。**同一个应用进程、仅关闭面板
就丢稿**，不符合报告“只在进程退出时丢失失败草稿”的边界说明。

要求：关页/关面板时处理全部待保存草稿，成功才移除；失败时选择合理的可恢复
策略，例如保留明确提示的编辑页或有界应用级草稿。具体方法由执行者判断，不要求
正常操作增加弹窗，也不要求无限缓存。补“切 A 失败 → 切 B → 故障恢复 → 关面板
→ 重开”及故障仍持续的场景；同时验证关闭后没有继续运行的备注轮询。

### CR-U04：备份/恢复入口与恢复后的界面一致性未交付

[节点 A 裁定 A-3](V1_2_CONTROLLER_REVIEW_A.md) 接受的是 UI **随 V12-05
交付**；[上轮响应](V1_2_RECHECK_RESPONSE.md)也明确重申此项。当前 UI 下没有
create_manual_backup/list_backups/restore_from_backup 调用，亦无
store_available/unavailable_reason 消费。不能以服务 API 存在代替用户入口。

另有独立复现：保存 `snapshot old note` 并备份 → 改成 `newer note` → 打开
备注 → 服务恢复备份成功。磁盘已是 `snapshot old note`，编辑器仍显示
`newer note`。refresh 只重建树且屏蔽 selection 信号，没有同步当前备注。
因此交付报告“备份后恢复一致性由广播与刷新保证”不成立。

要求：补显式备份、候选列表/验证状态及恢复入口。真实恢复前处理未保存草稿并让
用户了解覆盖范围；区分完整成功、磁盘已恢复但重开失败、普通失败。健康/降级
状态变化要重新控制所有写入口，不能只在 TodoPage 构造时读取一次 available。
恢复后树、计数、焦点、选择与备注从新存储同步；不要把恢复前的陈旧编辑器自动
写回覆盖恢复结果。覆盖恢复同一任务 ID、当前任务消失、有未保存草稿、仅重开
失败及再次恢复自修复。这是既定工作，不需要再向用户请求范围裁定。

### CR-U05：独立维度的中间态从分类视图消失

位置：`TodoPage::_task_view_keys()`，第 324–326 行。

在未分类视图给新任务仅点击一次“切换重要”，实际为 high/None；任务从当前
列表消失，四个象限与未分类均显示 0，而进行中显示 1。任务仍可在进行中找到，
并非数据库丢失，但用户无法在分类入口继续把它分配完整。

要求：任一维度为空即留在未分类；两维完整才进入唯一确定象限。覆盖
None/high/low 的 3×3 组合与按钮逐次操作（让事件循环在两次点击之间刷新）。
切回 None 时反馈应清楚显示未分类，不能保留前一次“高/低”的成功文案。
现有测试把连续两次点击写在同一事件回合，遗漏了单维中间状态。

### CR-U06：懒加载缓存使清空备注被跳过

位置：`todo/service.py::set_note()`，第 231–233 行。

复现：写入非空备注并关库 → 新建 TodoService → 未先调用 note_for，直接
set_note(id, "") → 再读，仍为原非空备注。repository 的新主树读取故意不带
note，Task.note 默认空串；服务却用它做相等短路，导致清空没有落盘且无报错。

要求：写入不能依赖未加载内容的相等比较。可显式区分加载状态、查询当前备注或
直接专用写入，由执行者选择。测试新服务中非空→空、空→非空、相同内容以及
其他字段编辑不会覆盖备注。顺带核对 note_for/set_note 把访问过的所有备注
塞回长期 _tasks 缓存的策略，避免关面板后仍累计保留大批正文。
