# RetirementPet 异步开发与主控验收流程

本文是执行者、本地定时任务、主控审阅者和用户之间的共同协议。版本工单记录某一版
“做了什么”；本文规定每一轮以后都“怎样做”。

## 1. 角色

### 执行者

执行者通常是本地 H 或一次性实施任务。它负责读取需求、调查、设计、编码、测试、
候选准备与执行报告。执行者可以派遣子 Agent，但子 Agent 的输出必须由执行者复核，
不能代替最终证据。

执行者不得：

- 审核并签收自己的实现；
- 将实现分支直接合并到 `main`；
- 推送公开仓库或发布 GitHub Release；
- 为了满足定时任务而强行修改代码或递增版本；
- 直接写用户 Todo 数据库。

### 主控审阅者

主控通常是 Codex。它负责核对提交范围、独立复现、构造反例、审计候选身份和公开
边界，并给出 `ACCEPTED`、`REWORK_REQUIRED` 或 `BLOCKED`。

主控通常不替执行者修改生产代码。主控可以：

- 运行只读检查、测试、构建到临时路径和公开快照审计；
- 编写并提交本周期的审阅记录；
- 直接完善审阅中发现的低风险收尾问题，包括文档、测试、工作流校验、格式和证据
  登记；这类修改必须写入审阅记录并复跑受影响检查；
- 在得到用户授权且审阅通过后，将实现分支快进合并到本地 `main`。

涉及产品行为、用户数据或 schema、协议语义、权限与隐私、素材与许可、迁移、候选
身份或较大范围代码变更时，主控仍提供可复现反例和验收条件，由执行者返工。主控
直接完善的低风险变更视为对执行者初稿的收口；不得借此绕过独立验收或签收自己作出
的实质产品变更。

### 用户

用户决定产品方向、素材授权、重大范围、正式发布以及需要真实设备参与的门禁。

## 2. 状态机

`CURRENT_STATE.md` 的 `status` 只能使用以下值：

| 状态 | 下一位行动者 | 含义 |
| --- | --- | --- |
| `READY_FOR_IMPLEMENTATION` | 执行者 | 周期已建立，可以调查和实施 |
| `IMPLEMENTING` | 执行者 | 实施尚未完成，主控不提前验收 |
| `READY_FOR_REVIEW` | 主控 | 执行报告和提交已冻结 |
| `REWORK_REQUIRED` | 执行者 | 先关闭审阅问题，不开启新范围 |
| `ACCEPTED` | 用户/主控 | 可按授权合并；正式发布仍单独决定 |
| `BLOCKED` | 用户 | 缺少必要授权、环境或产品决定 |
| `SKIPPED_BUSY` | 用户/下次任务 | 同机已有任务占用，本次未工作 |
| `NO_CHANGE` | 用户 | 巡检没有发现值得实施的改动 |

每次状态变化都必须与对应文档和 Git 提交一起发生，不能只在聊天中宣布。

## 3. 周期目录与记录

每轮使用 `YYYY-MM-DD-NNN` 形式的 `cycle_id`：

```text
docs/agent-workflow/cycles/<cycle_id>/
├── BRIEF.md
├── EXECUTION.md
└── REVIEW.md
```

- `BRIEF.md`：需求来源、基线、边界和初始验收方向。
- `EXECUTION.md`：执行者填写最终实现、提交、测试、候选和遗留项。
- `REVIEW.md`：主控填写独立复验、反例、裁定和下一步。

`EXECUTION.md` 和 `REVIEW.md` 从模板复制，已有记录不得覆盖。返工继续写在同一周期，
以带编号的章节追加，或创建 `EXECUTION-R2.md`、`REVIEW-R2.md`。

## 4. 无跨会话通信时的交接

Git 是邮箱。执行者在 `automation/<cycle_id>` 分支上工作，并将状态文档、代码和证据
提交到同一分支。最终消息必须报告分支、完整 HEAD 和执行报告路径。

交接身份用两个机器可验证字段记录在 `CURRENT_STATE.md`：`implementation_head`
是实现变更（代码、测试与非交接文档）链上最后一个提交；`handoff_head` 是承载
最终执行报告的交接提交。交接提交之后必须有且仅有一个**登记提交**作为分支
HEAD：它把 `handoff_head` 写入状态并翻转状态位，只允许修改以下两个精确文件：

- `docs/agent-workflow/CURRENT_STATE.md`；
- `CURRENT_STATE.md` 的 `execution_report` 字段指向的本周期执行报告。

`tests/test_agent_workflow_governance.py` 在状态
为 `READY_FOR_REVIEW` 时强制校验：两字段存在、完整 40 位十六进制、可解析、
`implementation_head` 是 `handoff_head` 的祖先，且 HEAD 的直接父提交恰为
`handoff_head`、`handoff_head..HEAD` 不触碰上述精确集合之外的路径；
执行报告的首个 YAML 头必须与状态中的身份一致。公开快照（根目录存在
`PUBLIC_SNAPSHOT_MANIFEST.json`）不含内部提交对象，依赖内部 Git ancestry 的登记
集成检查在其中显式 SKIP；报告—状态一致性与纯校验器反例仍运行。主控只以
`handoff_head` 为审阅与冻结对象，并另行记录登记 HEAD。

主控从该分支读取文件并验收。主控的审阅记录也提交到该分支；执行者下一次运行时
先搜索最新 `REWORK_REQUIRED` 周期并处理，不依赖旧会话上下文。

如果调度系统为任务创建独立 worktree，保留它；不要在另一个正在使用的 worktree 中
强制切换分支。

## 5. 同机互斥

开始实质工作前，执行者或主控应尝试原子创建目录：

```text
%TEMP%/RetirementPet-agent-workflow.lock/
```

并写入 `owner.json`，至少包含角色、周期、PID、开始时间和工作树路径。目录已存在时，
不得删除或抢占；将本次状态报告为 `SKIPPED_BUSY`。锁超过 12 小时也不能自动删除，
应交由用户确认是否为崩溃遗留。正常退出时由锁的创建者删除。

该位置由同一 Windows 用户的不同会话和 Git worktree 共享，不进入 Git。不得把用户名、
绝对工作树路径或锁内容复制进公开文档。

## 6. 需求输入与范围选择

执行者按以下顺序取输入：

1. 本周期上一份主控审阅中的 P0/P1 返工；
2. `宠物优化` Todo 树中明确、仍开放的产品需求；
3. `FUTURE_WORK.md` 与 `IMPLEMENTATION_STATUS.md` 的开放项；
4. 可复现的错误、性能数据和用户反馈；
5. 执行者调查发现、且能说明用户价值的新问题。

个人论文、教学和其他项目 Todo 不得复制进本仓库。

需求可能已经被旧实现部分满足。执行者必须先对照当前代码和真实运行行为，再决定是
关闭陈旧 Todo、补齐缺口还是建立新工单。

## 7. 每日巡检与版本实施

每日定时任务可以直接执行巡检，不得创建另一个自动任务。巡检允许：

- 读取状态文档、Git、产品 Todo 和日志；
- 运行只读状态命令与合适的测试；
- 更新调查报告和版本工单草稿；
- 若当前周期已经明确授权实施，则在受控分支继续该周期。

巡检不应自动执行版本发布、公共推送、用户数据迁移演练、角色切换、媒体控制、桌宠
退出或重启。大规模版本实施可以由用户另行启动一次性任务。

## 8. 执行交付最低要求

执行者交付 `READY_FOR_REVIEW` 前至少提供：

- 基线与最终完整提交哈希；
- 最终变更范围和未做内容；
- 与需求逐项对应的实现说明；
- 关键反例和测试结果；
- 若有候选：commit、build_id、receipt、EXE SHA-256 和证据目录；
- 若有素材：来源、许可、版本、确定性构建和接触图；
- 公开快照影响；
- 对正在使用的桌宠和用户数据的影响。

执行者不得用“全量绿”代替具体行为证据。

## 9. 主控审阅最低要求

主控先验证身份，再验证功能：

1. 工作树、分支、提交范围与候选身份；
2. 执行者声称的关键路径；
3. 环境差异、异常和边界反例；
4. 用户数据、PetPack、素材许可和隐私边界；
5. 公开快照与发布材料；
6. 全量回归和必要的真实桌面门禁。

环境缺失必须记为 `SKIP` 或 `PENDING_ENVIRONMENT`，不能伪造 PASS。主控裁定只对明确
列出的提交和候选有效；生产代码一旦变化，旧候选不能继承新结论。

## 10. 合并、版本与发布

- 普通周期不要求每天递增版本。
- 小版本号只在已验收变化形成清晰用户价值时收敛。
- PetPack 新内容使用新版本，不覆盖旧版本。
- 合并本地 `main`、构建 Alpha 候选和公开发布是三个独立动作。
- 公共仓库继续走“内部仓库 → 脱敏快照 → 公共功能分支 → PR → CI/审核 → main”。

## 11. Agent CLI 与数据库

运行实例支持协议时，所有在线 Todo 操作走 Agent CLI。若 CLI 因旧运行版本而不可用，
允许在用户授权的调查中用 SQLite `mode=ro` 做只读检查；不得直接写数据库。需要修改而
CLI/UI 又不能完成时，将其记录为产品缺口或 `BLOCKED`。
