## 调查优先级

1. 先复现并补齐 CLI 写能力缺口。这是后续自动任务安全维护 Todo 的基础设施。
2. 清点各角色每个语义动作的 static/sequence 事实，复现用户看到的裁切/残背景，并把
   “局部修整”与“全动作动画完成”分开验收。
3. 对 Markdown 做技术切片。优先交付安全、可回滚、不会破坏原始备注的最小闭环。
4. 评估重要/紧急与周期信息的视觉层级，避免与 Markdown 工作互相扩张。
5. 为媒体联动提供不改变默认设置的用户验收步骤；只有启用后复现失败才修改代码。

这些内容很可能超过单一小提交。执行者应形成节点化工单，优先交付能独立验收的基础
节点，不得把未完成的动作素材或未经用户验证的媒体链路写成整版完成。

执行者可以调整顺序，但必须在执行报告中给出依据。

## 与旧 V1.3 工单的关系

V1.3 工单中“Markdown 只做轻量预览、不承诺 WYSIWYG”是上一版本的范围冻结，不是永久
产品禁令。2026-09-19 的新 Todo 明确提出原生编辑与渲染，因此本周期可以重新调查和
设计；但不能直接把完整 Obsidian 能力当成本轮必交，仍需按安全性和实现成本切片。

同样，旧工单允许返工后继续无依赖工作；本异步流程为了防止跨会话范围漂移，采用更
严格规则：`REWORK_REQUIRED` 时先关闭 P0/P1，达到 `READY_FOR_REVIEW` 后停止并交主控。
