# RetirementPet Alpha 初步试用说明

> 文档关系：[文档中心](README.md) · [当前实施状态](IMPLEMENTATION_STATUS.md) ·
> [项目更新](PROJECT_UPDATES.md) · [角色库扩展指南](CHARACTER_LIBRARY_GUIDE.md)
>
本说明只适用于通过当前 `release-receipt.json` 和 Alpha acceptance bundle 绑定的
完整 `RetirementPet` 目录。不要把旧 EXE、新 `_internal` 或另一份 receipt 混在
一起。`ALPHA-GO` 表示可在当前用户机器上可回滚试用，不表示正式发布认证完成。

## 1. 试用前

1. 从托盘正常退出正在运行的 RetirementPet。旧版与 1.1.1 共用单实例名称；若
   1.1.0 仍在运行，双击新 EXE 只会唤起旧进程并立即退出新进程，因而仍显示旧
   简笔猫且不会出现一次性角色选择。
2. 保存当前使用的完整程序目录。将实际数据目录整体复制到另一个备份目录：默认
   是 `%APPDATA%\RetirementPet\`；若设置了 `RETIREMENT_PET_DATA_DIR`，则备份该
   变量指向的目录。若存在 `tasks.db-wal` 或 `tasks.db-shm`，必须和 `tasks.db`
   一起保留。
3. 确认候选目录至少包含：
   `RetirementPet.exe`、`_internal\build-info.json`、`_internal\assets` 和
   `_internal\config`。
4. 打开验收命令所打印 Evidence 目录内的 `acceptance.json`，确认
   `alpha_trial_verdict` 为 `ALPHA-GO`，并接受
   `production_release_verdict` 仍是 `PRODUCTION-NO-GO:PENDING_ENVIRONMENT`。
   候选或 receipt 不匹配通常是 `ALPHA-NO-GO`；只有前提或证据不足、工具超时等
   无法判定的运行才是 `INVALID_RUN`。

## 2. 第一次启动

双击完整目录中的 `RetirementPet.exe`。预期结果：

- 桌面出现透明、无标题栏的退休猫和倒计时；桌宠本体不成为普通任务栏窗口；
- 1.1.1 尚未完成角色选择时，会同时打开一次标准控制面板并进入“角色”页。可以
  继续官方猫，或确认本地内容边界并启用半写实猫；直接关闭不会记录选择；
- 角色轮廓应清晰，动作标题不应再出现 `□□□`；标题通常显示中文，系统没有可用
  中文字形时会显示稳定的英文后备文案；
- 托盘出现 RetirementPet 图标；
- 再次双击 EXE 不产生第二只宠物，而是唤起现有实例；
- 右键桌宠或托盘能打开菜单；
- 从托盘选择“退出”后，窗口和托盘图标都正常消失。

若启动后完全看不到桌宠，先从托盘执行“显示桌宠”“关闭鼠标穿透”和“恢复到主
屏幕”。仍不可见时退出，不要反复覆盖数据目录，按第 7 节回滚。

## 3. 建议的 15 分钟试用路径

### 桌宠与动作

- 拖动桌宠，双击折叠/展开倒计时；
- 切换置顶，再切回；
- 开启鼠标穿透，确认桌宠仍可见，再从托盘恢复；
- 打开控制面板 → 动作，关闭/开启随机小动作；关闭面板并重开，确认值保持；
- 在声音与日程页保存一个合法时间；输入 `99:99` 应被拒绝而不是覆盖旧值。

### 待办

1. 分别从桌宠右键菜单和托盘右键菜单选择“打开待办”，确认都直接进入同一个待办页；
2. 关闭/隐藏面板，在 Windows 的其他普通窗口中按 `Ctrl+Alt+T`，确认同一控制面板
   被唤起并切到待办页；若系统快捷键已被其他程序占用，确认桌宠仍能启动并记录日志，
   然后继续使用右键入口；
3. 在“短期”中新建一个根任务；
4. 为它添加两级子任务并重命名；
5. 用“上移/下移”调整同级顺序，完成其中一个子任务，再恢复；
6. 为一个任务设置截止日期；
7. 开始专注该任务，再专注另一任务，确认同一时间只有一个焦点；
8. 退出并重启，确认树、顺序、完成状态、截止日期和焦点都恢复。

Todo 最多支持六层任务树。删除父任务会删除整个子树且不可撤销，请先确认内容。
Todo 初始化或存储异常时，页面进入不可用、禁止写入状态，可能不展示原任务，并
提示“任务文件未作改动”；这不应导致桌宠本体退出。不要把空视图误判为数据已
丢失，也不要尝试新建空库：先退出、保存现场和备份，再排查。不要在程序运行时
用数据库工具修改 `tasks.db`。

首次用 1.2.0 打开旧版本的待办数据时，程序会自动把 `tasks.db` 升级到新格式：
升级前先在同目录 `backups/` 下生成一份经过校验的迁移前备份（数量有上限，
但最近一份迁移前备份始终保留），迁移在单个事务内完成，中途失败会回滚，
旧数据原样保留，可再次尝试；备份生成失败时不会开始迁移。注意：旧版本程序
不能直接读写新格式。如果想回退到旧版应用，必须先用当前版本的恢复入口还原
一份旧格式备份，且回退后的数据不包含该备份之后新增的任务；“迁移失败自动
保留原数据”与“主动回到旧版”是两回事，不要混用。

### 角色与预览页

- 首次选择区应只出现一个。先直接关闭并重启，确认它仍会出现；随后二选一：选择
  “继续使用官方退休猫”并确认再次启动不重复询问，或选择“确认本地内容并启用
  半写实猫”，让检查在后台进行并在成功后直接安全切换。若已选择官方猫，仍可用
  下方普通导入入口导入随附预览，再从角色列表手动切换；
- 当前只有一个官方退休猫时，角色列表应选中当前角色并禁用无意义的切换，同时
  明确提示“当前仅有一个角色”；
- 点击“导入本地角色包…”，文件选择器应默认打开随附示例目录；选择
  `realistic-retirement-cat-0.1.1.petpack`，确认检查在后台进行；确认框必须固定显示
  “本地内容”、声明发布者身份未验证、权利自述未验证、文件体积/能力和警告代码。
  先取消一次并确认角色库未变，再确认导入，检查提示“导入成功”且活动角色未自动
  改变；随后手动切换到“半写实退休猫”，再切回官方退休猫；
- 退出并重启，确认最后一次明确选择能够恢复；导入损坏文件时应显示失败并保持旧
  角色、ACTIVE 与 last-known-good；
- 文案页是“不保存、不应用”的安全预览；
- 布局与可见性下拉框已禁用，只展示未来配置形态；
- 不要手工修改 `_internal`、角色库数据库或将第三方 ZIP 直接改名为 `.petpack`。

若数据目录中保存的是 1.0.0 内置退休猫，首次启动 1.1.0 会先精确恢复旧角色，再
通过安全切换事务迁移到随程序保留的内置角色 Revision 1.0.1。旧事实和
last-known-good 不会被覆盖；第三方活动角色不会触发此次迁移。

## 4. 开机自启试用

从托盘勾选“开机自动启动”，随后重新打开菜单确认状态。此操作只写当前用户的
HKCU Run 值，不需要管理员权限。移动安装目录后使用“修复开机自启”。

Alpha 自动门禁验证了命令正确引用当前 EXE、`--startup` 正常显示且不抢焦点；
开机启动本身不会打开首次角色选择面板；尚未选择时，下一次手动双击 EXE 才会
唤起同一运行实例并进入角色页。
真实注销/登录尚属于 Production 人工门禁。若你愿意验证，请先保存其他工作，
注销再登录，记录是否自动出现、是否抢焦点以及显示延迟是否合理。

## 5. 数据与隐私

所有持久数据默认在 `%APPDATA%\RetirementPet\`；设置了
`RETIREMENT_PET_DATA_DIR` 时，以该变量指向的目录为准：

- `settings.json`、`state.json`；
- `tasks.db` 及 SQLite 辅助文件；
- `library\` 角色库；
- `logs\` 日志和性能 marker。

程序默认不联网、无遥测，不保存按键内容；活跃/空闲判断只读取系统提供的最后
输入时间。日志不应包含用户选择音乐文件的完整路径或底层异常原文。

## 6. 已知限制

- 只有一个自动启用的官方角色；本地导入已开放，但当前严格限定为透明 PNG 的
  `static/sequence`，且没有普通用户卸载 UI；
- 随附半写实猫 `0.1.1` 是静态画风预览：idle/work/rest 共用母版，其他动作回退
  idle，尚未承诺独立姿态或逐帧动画；
- 文案和布局页仅预览；
- Todo 无云同步、协作、附件和自然语言解析；
- `Ctrl+Alt+T` 由 Windows 全局注册；若同一组合已被其他程序占用，本次运行会停用
  快捷键但保留两个右键入口，不影响 Todo 数据或桌宠主功能；
- 会议不接入第三方日历，音乐不含在线曲库；
- 内置退休猫已改用 512px 无文字正文素材和实时引擎文字层，但美术造型仍是参考
  画风；角色协议与运行时已为后续高质量动画留出扩展点；
- Production 的 24 小时、干净 VM、多屏 DPI、睡眠/唤醒和多机性能门禁未完成。

## 7. 回滚

1. 从托盘正常退出；若进程无响应，记录日志后再结束进程，强杀不算正常退出。
2. 将当前完整程序目录移到旁边保留，不要把新旧 `_internal` 混合。
3. 恢复第 1 节保存的上一份完整程序目录。仅在同一构建机原先已有公开产物时，
   可信构建才可能在对应 `.release\<run>\previous-RetirementPet\` 留有副本；不要
   把它当作试用者唯一的回滚来源。
4. 默认同时恢复第 1 节的整个实际数据目录备份。旧程序不保证能读取新版本写过的
   数据；不要先用旧程序直接打开新数据来碰运气。
5. 启动旧版，并在路径变化时修复开机自启。

## 8. 反馈时请附带

- 问题发生时间和可复现步骤；
- Alpha acceptance 报告中的 `artifact.build_id`、`receipt.artifact_id` 与
  `receipt.exe_sha256`；
- Windows 版本、屏幕数量和缩放比例；
- 实际数据目录下 `logs\` 中对应时间段的日志。

请先检查日志中是否含个人路径或其他敏感信息，再决定是否分享。无需上传
`tasks.db`、音乐文件或完整数据目录。

当前已知问题和 Production 环境门禁见[未来工作](FUTURE_WORK.md)。
